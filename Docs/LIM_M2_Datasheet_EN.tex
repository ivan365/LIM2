\section{Document Scope and Architectural Philosophy}
This document serves as the formal architectural reference manual and hardware specification for the \textbf{LIM M2} microprocessor. The LIM M2 architecture has been deliberately designed to deliver deterministic execution, robust electrical integrity, and superior clock scaling.

A defining cornerstone of the LIM M2 datapath is the \textbf{total elimination of internal tri-state (high-impedance / Hi-Z) buses}. By substituting shared capacitive wires with actively driven multiplexer trees (Point-to-Point MUX Routing), the architecture prevents shoot-through currents, eliminates bus contention risks, and guarantees sharp, symmetrical transition edges.

\begin{limnote}{Instruction Code Allocation}
The LIM M2 instruction set architecture utilizes a contiguous 5-bit primary opcode space:
\texttt{NOP}=0, \texttt{ADD}=1, \ldots, \texttt{MSP}=26. Opcode values 27--31 are reserved for next-generation hardware extensions.
\end{limnote}

\subsection{Unified Instruction Syntax Philosophy}
The LIM M2 processor architecture strictly enforces an orthogonal operand convention: \textbf{the destination operand (target, "where to") is always declared first, followed by input source operands ("where from")}. This ensures clean, deterministic code structure across all instructions:
\begin{itemize}
  \item \textbf{Arithmetic Operations (3 Operands):} \texttt{ADD Rd, Rs1, Rs2} denotes $\text{Rd} \leftarrow \text{Rs1} + \text{Rs2}$ (e.g., \texttt{ADD R0, R1, R2} computes $R0 = R1 + R2$); similarly for \texttt{SUB}, \texttt{MUL}, \texttt{DIV}.
  \item \textbf{Logic Operations (2 Operands):} \texttt{AND Rd, Rs} denotes $\text{Rd} \leftarrow \text{Rd} \ \text{AND}\ \text{Rs}$ (e.g., \texttt{AND R0, R1} computes $R0 = R0 \ \& \ R1$); similarly for \texttt{OR}, \texttt{NAND}, \texttt{NOR}, \texttt{XOR}, \texttt{XNOR}.
  \item \textbf{Bitwise Inversion NOT (1 Operand, 1-byte instruction):} \texttt{NOT Rd} denotes $\text{Rd} \leftarrow \sim\text{Rd}$ (e.g., \texttt{NOT R0} computes $R0 = \sim R0$). Encoded in exactly 1 byte (\texttt{[7:3]} opcode, \texttt{[2:0]} Rd), no second byte is fetched from memory.
  \item \textbf{Register-to-Register Transfers:} \texttt{LRR Rd, Rs} executes a direct point-to-point copy from source (point B, \reg{Rs}) to destination (point A, \reg{Rd}): $\text{Rd} \leftarrow \text{Rs}$ (e.g., \texttt{LRR R0, R1} computes $R0 = R1$).
  \item \textbf{Memory Loads (LMR):} the primary register argument \reg{Rd} designates the processor register receiving loaded data.
\end{itemize}

\section{Processor Overview}
The \textbf{LIM M2} is a versatile, high-throughput 16-bit microprogrammed processor engineered for integer-intensive computation. Architectural highlights include:

\begin{itemize}
  \item \textbf{Conflict-Free Multiplexer Datapath:} Internal signals are steered purely by push-pull multiplexer trees (\textbf{MUX 1}, \textbf{DEST-DMUX}, and \textbf{MUX 2}). This modern design is perfectly suited for high-density ASIC and modern FPGA synthesis.
  \item \textbf{Dual Accumulator Staging:} Dedicated pre-ALU accumulators (\reg{ACCA} and \reg{ACCB}) isolate the arithmetic core from the general register file, minimizing propagation path skew.
  \item \textbf{Hardware ALU Auto-Chaining (Multi-Word Arithmetic):} The ALU integrates an internal residual register (\reg{ALU\_RESIDUAL}). When an addition overflows 16 bits ($>2^{16}-1$), a subtraction produces a borrow ($<0$), or multiplication/division produces high-word residuals, the excess is retained in hardware and automatically accumulated or subtracted in the next mathematical operation. This enables continuous multi-word arithmetic (32, 48, 64+ bits) without dedicated ADC/SBB instructions. The chain is flushed using \texttt{NOP}.
  \item \textbf{Direct Reg-to-Reg Bypass:} A low-latency path from MUX 1 directly into MUX 2 enables single-cycle register transfers without locking ALU resources.
  \item \textbf{Linear 24-Bit Addressing (Up to 16 MB):} Dedicated 24-bit pointer registers (\reg{PTREG} with auto-increment and \reg{SREG} stack pointer) transcend the traditional 64 KB memory barrier, providing linear access across 16 megabytes of data and stack space.
  \item \textbf{High Clock Scaling Potential:} Unburdened by capacitive bus decay, the LIM M2 operates comfortably at a baseline frequency of \textbf{200~MHz}, scaling toward \textbf{700~MHz and above} in optimized silicon.
\end{itemize}

\section{Detailed Instruction Specifications}
The following pages detail the formal execution profiles for all 32 opcode allocations.

\InstructionPage{NOP}{00000}{Control}{Hardware No-Operation and Pipeline Flush}{%
\small
Syntax:    NOP \\
Operation: PC <- PC + 1, ALU\_RESIDUAL <- 0, FREG.CF <- 0, FREG.OF <- 0 \\[2pt]
Example:   NOP              ; Flush ALU carry chain, align cycles
}{No operands required; \field{cfg} field reserved for delay calibration.}{Clears carry (CF), overflow (OF), and borrow tracking flags; preserves other flags.}{Performs pipeline cycle alignment and flushes the internal ALU residual accumulator, terminating any chained multi-word carry/borrow sequence before starting new independent calculations.}
\InstructionPage{ADD}{00001}{Arithmetic}{Addition with Automatic Multi-Word Carry Chaining}{%
\small
Syntax:    ADD arg0(REG), arg1(REG), arg2(REG) : arg0 = arg1 + arg2 \\
Operation: sum <- arg1 + arg2 + ALU\_RESIDUAL \\
           arg0 <- sum[15:0], ALU\_RESIDUAL <- (sum > 0xFFFF ? 1 : 0) \\[2pt]
Example:   ADD R0, R1, R2   ; R0 = R1 + R2 (registers R0--R7)
}{GPRs R0--R7, accumulators ACCA/ACCB, or immediate operands.}{Sets carry flag CF and overflow OF if sum exceeds $2^{16}-1$; updates ZF based on dst.}{Delivers seamless multi-word arithmetic (32, 48, 64+ bits). If the addition exceeds 16 bits ($>2^{16}-1$), the carry (+1) is latched into the internal ALU residual register and automatically added during the subsequent ADD operation without requiring distinct ADC opcodes. The lower 16 bits are deterministically stored in dst. The chain is reset via NOP or overwritten by a new operation.}
\InstructionPage{SUB}{00010}{Arithmetic}{Subtraction with Automatic Multi-Word Borrow Chaining}{%
\small
Syntax:    SUB arg0(REG), arg1(REG), arg2(REG) : arg0 = arg1 - arg2 \\
Operation: diff <- arg1 - arg2 - ALU\_RESIDUAL \\
           arg0 <- diff[15:0], ALU\_RESIDUAL <- (diff < 0 ? 1 : 0) \\[2pt]
Example:   SUB R0, R1, R2   ; R0 = R1 - R2 (registers R0--R7)
}{GPRs R0--R7, constants, or accumulators ACCA/ACCB.}{Sets borrow flag (CF) and OF on negative result ($< 0$); updates ZF.}{Enables continuous multi-word subtraction. When a borrow occurs ($< 0$), the borrow ($-1$) is retained in the internal ALU register and automatically subtracted during the next SUB operation. The lower 16-bit word is deterministically preserved in dst. Inserting a NOP breaks the chain for independent subtraction.}
\InstructionPage{MUL}{00011}{Arithmetic}{Multiplication with Upper Word Residual Retention}{%
\small
Syntax:    MUL arg0(REG), arg1(REG), arg2(REG) : arg0 = arg1 * arg2 \\
Operation: prod <- arg1 * arg2 \\
           arg0 <- prod[15:0], ALU\_RESIDUAL <- prod[31:16] \\[2pt]
Example:   MUL R0, R1, R2   ; R0 = R1 * R2 (upper 16 bits in ALU\_RESIDUAL)
}{GPRs R0--R7, accumulators ACCA/ACCB.}{Updates ZF; sets OF/CF if the upper 16 bits of the product (prod[31:16]) are non-zero.}{For 32-bit products exceeding the 16-bit register width, the low 16 bits are placed into dst, while the upper 16 bits are retained in the internal ALU residual register. In a subsequent addition, this residual is automatically accumulated (hardware MAC support / bigint multiplication). The upper word can also be extracted by adding the register to itself after clearing. Executing NOP flushes the residual register.}
\InstructionPage{DIV}{00100}{Arithmetic}{Division with Remainder Latched in ALU Residual}{%
\small
Syntax:    DIV arg0(REG), arg1(REG), arg2(REG) : arg0 = arg1 / arg2 \\
Operation: arg0 <- arg1 / arg2 \\
           ALU\_RESIDUAL <- arg1 \% arg2 \\[2pt]
Example:   DIV R0, R1, R2   ; R0 = R1 / R2 (remainder modulo in ALU\_RESIDUAL)
}{GPRs R0--R7, accumulators ACCA/ACCB.}{Sets EM (Error Math) flag on division by zero without core stall; updates ZF.}{Stores the integer quotient in dst while preserving the remainder (modulo) in the internal ALU residual register for immediate reuse in subsequent operations or clearing via NOP.}
\InstructionPage{LMR}{00101}{Memory}{Load External Data and Memory into Register}{%
\small
Syntax:    LMR arg0(REG), <SRC\_MODE> : arg0 = MEM[...] \\
Modes:     SRC=0: LMR R0, [PC+]          ; Imm Data (1--2 bytes) \\
           SRC=1: LMR R0, [[PC+]]        ; Imm Pointer \\
           SRC=2: LMR R0, [PTREG]        ; Pointer reg (AIP auto-inc) \\
           SRC=3: LMR R0(R\_hi), R1(R\_lo) ; 24-bit composite address \\
Operation: arg0 <- MEM[EA] (upper address bits in R0 overwritten) \\[2pt]
Example:   LMR R0, R1       ; EA=(R0<<16)|R1, load MEM[EA] into R0
}{%
\textbf{Octet 0:} bit $[8]$ (\field{SZ}) specifies operand width ($0 = 1$ byte, $1 = 2$ bytes / word); bits $[10:9]$ (\field{SRC}) select the data source ($0$ --- immediate literal following instruction, $1$ --- immediate pointer following instruction, $2$ --- indirect via 24-bit pointer register \reg{PTREG}, $3$ --- indirect via register pair).\\
\textbf{Octet 1:} bits $[7:5]$ select register \reg{Arg1} (\reg{R\_hi} / destination), bits $[4:2]$ select register \reg{Arg2} (\reg{R\_lo}). Under $\field{SRC} = 3$, the user specifies two 16-bit registers forming a 32-bit number, of which 24 bits are used in practice for physical addressing: \reg{Arg1} holds upper address bits and \reg{Arg2} holds lower 16 address bits. Notably, \reg{Arg1} also acts as the destination register: upon memory retrieval, the upper address bits in \reg{Arg1} are overwritten with the loaded data.%
}{All flags in status register \reg{FREG} are preserved without alteration.}{%
The \texttt{LMR} instruction is the fundamental ingestion pathway bringing external data and memory into the LIM M2 general-purpose register file ($R0$--$R7$). The architecture unifies four orthogonal modes with native 24-bit addressing:\\
1. Under $\field{SRC} = 0$, immediate literals ($1$ or $2$ bytes) are fetched directly from the instruction stream with automated \reg{PC} advancement.\\
2. Under $\field{SRC} = 1$, an immediate pointer is read from code space, followed by data dereferencing.\\
3. Under $\field{SRC} = 2$, memory is addressed via the dedicated 24-bit pointer register \reg{PTREG}. If the auto-increment flag \texttt{FREG.AIP} (bit 12) is active, \reg{PTREG} automatically advances by $+1$ or $+2$ in hardware, enabling single-cycle streaming array ingestion without software loop overhead.\\
4. Under $\field{SRC} = 3$, the user selects two 16-bit registers (\reg{Arg1} and \reg{Arg2}) forming a 32-bit value, of which 24 bits are used for memory addressing. The user specifies that the upper address bits are placed in \reg{Arg1} and the lower 16 bits in \reg{Arg2}. In this mode, register \reg{Arg1} (which held the upper address bits) also serves as the destination register: the retrieved data is saved into \reg{Arg1}, overwriting its previous high-address value, while \reg{Arg2} continues to retain the lower 16 address bits.%
}
\InstructionPage{LRM}{00110}{Memory}{Store Register Data into Memory and External Devices}{%
\small
Syntax:    LRM arg0(REG), <DST\_MODE> : MEM[...] = arg0 \\
Modes:     DST=0: LRM R0, [PC+]          ; Inline code memory \\
           DST=1: LRM R0, [[PC+]]        ; Imm Pointer \\
           DST=2: LRM R0, [PTREG]        ; Pointer reg (AIP auto-inc) \\
           DST=3: LRM R0(R\_hi), R1(R\_lo) ; 24-bit composite address \\
Operation: MEM[EA] <- arg0[15:0] (or low byte if SZ=0) \\[2pt]
Example:   LRM R0, R1       ; EA=(R0<<16)|R1, store R0 into MEM[EA]
}{%
\textbf{Octet 0:} bit $[8]$ (\field{SZ}) specifies operand width ($0 = 1$ byte, $1 = 2$ bytes / word); bits $[10:9]$ (\field{DST}) select the destination target ($0$ --- inline memory directly following instruction, $1$ --- immediate pointer following instruction, $2$ --- indirect via 24-bit pointer register \reg{PTREG}, $3$ --- indirect via register pair).\\
\textbf{Octet 1:} bits $[7:5]$ select source register \reg{Arg1} (\reg{Rs} / \reg{R\_hi}), bits $[4:2]$ select register \reg{Arg2} (\reg{R\_lo}). Under $\field{DST} = 3$, two registers form a 32-bit composite word of which 24 bits are used for physical addressing (\reg{Arg1} holds upper address bits and source data, \reg{Arg2} holds lower 16 bits). Overwriting existing data at the destination is the programmer's responsibility.%
}{All flags in status register \reg{FREG} are preserved without alteration.}{%
The \texttt{LRM} instruction is the fundamental egress pathway transferring register data from the LIM M2 general-purpose register file ($R0$--$R7$) to memory and memory-mapped I/O peripherals. The architecture unifies four orthogonal addressing modes:\\
1. Under $\field{DST} = 0$, the processor stores $1$ or $2$ bytes directly into memory following the instruction (\reg{PC}) with automated \reg{PC} advancement. This mode enables self-modifying routines and inline buffer writes; data destruction at the target address is the programmer's responsibility.\\
2. Under $\field{DST} = 1$, an immediate 16-bit pointer is read from code space, and data is stored to that dereferenced address.\\
3. Under $\field{DST} = 2$, memory is addressed via the dedicated 24-bit pointer register \reg{PTREG}. If the auto-increment flag \texttt{FREG.AIP} (bit 12) is active, \reg{PTREG} automatically advances by $+1$ or $+2$ in hardware, enabling single-cycle streaming array transfers without loop overhead.\\
4. Under $\field{DST} = 3$, two 16-bit registers are paired: \reg{Arg1} and \reg{Arg2} form a 32-bit composite integer, whose lower 24 bits specify the physical address ($\text{Addr}[23:0]$). Data from \reg{Arg1} is stored to the synthesized address, granting direct write access across the full 16 MB address space.%
}
\InstructionPage{LRR}{00111}{Transfer}{Register-to-Register Transfer (Copy from point B to point A)}{%
\small
Syntax:    LRR arg0(REG), arg1(REG) : arg0 = arg1 \\
Operation: arg0 <- arg1 (direct copy from source to destination) \\[2pt]
Example:   LRR R0, R1       ; R0 = R1 (value of R1 copied to R0)
}{%
\textbf{Octet 0:} opcode $00111_2$ (\texttt{0x07}), bits $[10:8]$ reserved ($000_2$).\\
\textbf{Octet 1:} bits $[7:5]$ define destination register \reg{Arg1} (\reg{Rd}, point A, receiving data); bits $[4:2]$ define source register \reg{Arg2} (\reg{Rs}, point B, providing data); bits $[1:0]$ set to $00_2$. When executed, \reg{Rs} is copied to \reg{Rd} in 1 microcycle.%
}{Preserves all status flags.}{%
The \texttt{LRR} instruction provides the foundational register-to-register move mechanism across general-purpose registers ($R0$--$R7$). It executes a direct transfer from source (point B) to destination (point A) via the dedicated hardware \textbf{MUX 1} $\to$ \textbf{MUX 2} bypass datapath without stalling the ALU and without affecting \reg{FREG} flags.%
}
\InstructionPage{CMP}{01000}{Compare}{Hardware Operand Comparison}{%
\small

\section{Interrupt Subsystem and Vector Processing}

The LIM~M2 interrupt subsystem is architected to guarantee deterministic low-latency real-time response, bus contention immunity, and atomic context switching. The architecture integrates external hardware service requests and internal software traps into a unified 16-vector hierarchy governed by a cycle-accurate hardware handshake.

\subsection{Hardware Handshake Protocol (RDI $\to$ IA $\to$ D0--D7)}
For robust peripheral interfacing, the processor implements a 4-phase hardware handshake cycle that completely eliminates CPU polling overhead:

\begin{enumerate}
  \item \textbf{Request Phase (RDI):} A peripheral device asserts an active-high level on the \texttt{RDI} (\textit{Raw Direct Interrupt}) pin. The core samples \texttt{RDI} at atomic micro-op boundaries.
  \item \textbf{Arbitration Phase (Mask Check):} If interrupts are enabled (\reg{FREG.MIE} = 1), the CPU commits the current datapath micro-operation and initiates the interrupt sequence.
  \item \textbf{Acknowledge Phase (IA Strobe):} The core asserts an active-high strobe on the \texttt{IA} (\textit{Interruption Accepted / Interrupt Acknowledge}, Pin~26) output. This informs all slave devices on the bus that the core is ready to ingest the interrupt vector index.
  \item \textbf{Vector Transfer Phase (D0--D7):} Concurrently with asserting \texttt{IA}, the processor switches the external bidirectional data bus \texttt{D0--D7} to input mode and activates the \texttt{RD} line. The requesting peripheral drives its 8-bit vector ID onto \texttt{D0--D7} (lower 4 bits address vectors 0--15).
  \item \textbf{Latch and Dispatch Phase:} The CPU latches the vector ID from \texttt{D0--D7}, deasserts \texttt{IA}, and advances to context preservation.
\end{enumerate}

\subsection{Context Preservation on 24-Bit Stack and Handler Entry}
Interrupt service entry is permitted strictly when the CPU is not already executing an interrupt handler (\reg{FREG.INTR} = 0) and master interrupts are unmasked (\reg{FREG.MIE} = 1). When \reg{FREG.INTR} = 1, subsequent hardware interrupt requests are locked out by hardware.

Upon interrupt acceptance, the core executes an atomic state preservation sequence:
\begin{enumerate}
  \item \textbf{Program Counter Preservation (PC):} The current instruction pointer is pushed onto the 24-bit execution stack via \reg{SREG}:
  $$\reg{SREG} \leftarrow \reg{SREG} - 2, \quad \text{Memory}[\reg{SREG}] \leftarrow \text{PC}_{15:0}$$
  \item \textbf{Status and Flags Preservation (FREG):} The complete status register (with \reg{FREG.INTR}=0) is pushed onto the stack:
  $$\reg{SREG} \leftarrow \reg{SREG} - 2, \quad \text{Memory}[\reg{SREG}] \leftarrow \reg{FREG}$$
  \item \textbf{Nested Interrupt Lockout:} The core asserts the in-interrupt flag \reg{FREG.INTR} $\leftarrow$ \texttt{1} (bit 15) and clears the mask bit \reg{FREG.MIE} $\leftarrow$ \texttt{0}, precluding nested re-entrancy and race conditions.
  \item \textbf{Vector Dispatch:} The handler address is indexed from the vector table using the ingested vector ID and loaded into \texttt{PC}.
\end{enumerate}

\subsection{Return from Interrupt}
Exiting the interrupt service routine restores the preempted execution context:
\begin{enumerate}
  \item The saved flags and processor modes are restored from the stack:
  $$\reg{FREG} \leftarrow \text{Memory}[\reg{SREG}], \quad \reg{SREG} \leftarrow \reg{SREG} + 2$$
  (Restoring \reg{FREG} automatically clears \reg{FREG.INTR} back to \texttt{0}, lifting the lockout, and restores \reg{FREG.MIE} to its previous state).
  \item The return address is popped back into the program counter:
  $$\text{PC} \leftarrow \text{Memory}[\reg{SREG}], \quad \reg{SREG} \leftarrow \reg{SREG} + 2$$
  \item Normal instruction execution seamlessly resumes on the subsequent clock cycle with zero data corruption.
\end{enumerate}

\section{Conclusion}
The \textbf{LIM M2} architecture harmonizes the time-tested reliability of deterministic microprogramming with the modern performance of an entirely tri-state-free multiplexer datapath. By eliminating bus contention, floating nodes, and capacitive decay, the LIM M2 guarantees exceptional signal fidelity and opens an unprecedented clock frequency envelope spanning from 200~MHz to the highest thresholds of modern silicon.
