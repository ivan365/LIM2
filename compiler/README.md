## 🚀 Использование из командной строки

### 1. Быстрая компиляция в `.bin` и `.hex`
Компилятор автоматически генерирует одновременно чистый бинарный файл (`.bin`) и шестнадцатеричный файл (`.hex`):

```bash
# Использование через compiler.py:
python3 LIM2/compiler/compiler.py LIM2/compiler/demo.asm

# Или напрямую через limasm.py:
python3 LIM2/compiler/limasm.py LIM2/compiler/demo.asm
```

### 2. Подробный листинг и дизассемблирование (`-l`)
Ключ `-l` (или `--list`) выводит таблицу всех меток и побайтовый дизассемблированный листинг инструкций:

```bash
python3 LIM2/compiler/compiler.py LIM2/compiler/demo.asm -l
```

Пример вывода:
```text
[LIM M2 ASM] Успешно скомпилировано: 97 байт (база 0x0000)
  -> BIN: /Users/.../LIM2/compiler/demo.bin
  -> HEX: /Users/.../LIM2/compiler/demo.hex

Таблица меток:
  START            = 0x0000

Машинный код:
  0x0000:  D0 01 00 00           MSP.ld $freg, 0x0000
  0x0004:  D4 41 00 10           MSP.or $freg, 0x1000
  0x0008:  D2 05 00 3F 00 00     MSP.ld $sreg, 0x00003F00
  0x000E:  29 20 64 00           LMR.w $1, 0x0064
  0x0012:  29 40 32 00           LMR.w $2, 0x0032
  0x0016:  08 28                 ADD $0, $1, $2
  0x0018:  A0                    INC $0
  0x0019:  AA                    DEC $2
  ...
```

### 3. Настройка выходных файлов и базового адреса
```bash
python3 LIM2/compiler/compiler.py my_code.asm -o build/firmware.bin -x build/firmware.hex -b 0x0000
```

## 📖 Спецификация языка ассемблера

### 1. Регистры
* **Регистры общего назначения (РOН, 16 бит):** `$0` .. `$7` (также принимаются `R0` .. `R7`).
* **Специальные системные регистры:**
  * `$ptreg` — 32-битный указатель адреса (`PTREG`, 4 ГБ)
  * `$freg` — 16-битный регистр статуса и флагов (`FREG`, бит 11: `PRV`)
  * `$sreg` (или `$sp`) — 32-битный указатель аппаратного стека (`SREG`)
  * `$ir0` .. `$ir15` — 16 векторов аппаратных прерываний (32-битные адреса)
  * `$pv0` .. `$pv13` — 14 регистров Зон Привилегий (32-битные границы 7 защищенных зон)
  * `$pv14` (`$rom_base`), `$pv15` (`$rom_limit`) — 2 регистра границ постоянной памяти ROM (32-битные границы ROM)

### 2. Суффиксы размера операндов
Инструкции обмена с памятью `LMR` и `LRM` поддерживают строго два размера (аппаратный бит `SZ`):
* `.b` (*byte*, 8 бит / 1 байт, `SZ=0`) — например: `LMR.b $0, 0x42`, `LRM.b $0, [0x1000]`
* `.w` (*word*, 16 бит / 2 байта, `SZ=1`, по умолчанию) — например: `LMR.w $0, 0x1234` или `LMR $0, 0x1234`
*(Для 24/32-битных данных используются директивы `dp`/`dd` и команда `MSP.ld`).*

### 3. Регистровая арифметика и унарные инструкции
```asm
ADD $0, $1, $2          ; $0 = $1 + $2 (также: ADD R0, R1, R1)
SUB $3, $0, $2          ; $3 = $0 - $2
MUL $4, $1, $2          ; $4 = $1 * $2
DIV $5, $4, $1          ; $5 = $4 / $1
MOD $6, $4, $1          ; $6 = $4 % $1
INC $0                  ; $0 = $0 + 1 (1-байтовая инструкция)
DEC $1                  ; $1 = $1 - 1 (1-байтовая инструкция)
NOT $2                  ; $2 = ~$2    (1-байтовая инструкция)
```

### 4. Режимы адресации памяти (`LMR` и `LRM`)
* **Число без скобок** — непосредственное значение (`SRC=0` / `DST=0`):
  ```asm
  LMR.w $0, 0x1234      ; $0 = 0x1234
  ```
* **Квадратные скобки `[addr]`** — прямая ссылка на память через 32-битный указатель (`SRC=1` / `DST=1`, 6 байт):
  ```asm
  LMR.w $0, [0x00001000] ; Чтение MEM16[0x1000] в $0 (2 байта префикс + 4 байта адреса Little-Endian)
  LRM.w $0, [0x00001000] ; Запись $0 в MEM16[0x1000]
  ```
* **Указатель в `PTREG` (`[$ptreg]`, `SRC=2` / `DST=2`):**
  ```asm
  LMR.w $0, [$ptreg]    ; Чтение слова по 32-битному адресу PTREG
  LRM.b $4, [$ptreg]    ; Запись байта $4 по адресу PTREG
  ```
* **Составной 32-битный поинтер из пары регистров `[$0:$1]` (`SRC=3` / `DST=3`):**
  ```asm
  LMR $0, [$0:$1]       ; Чтение по 32-битному адресу ($0 << 16) | $1
  LRM $2, [$0:$1]       ; Запись по 32-битному адресу ($0 << 16) | $1
  ```

### 5. Спецрегистры (`MSP`), векторы и цепочки указателей
```asm
MSP.and $freg, 0x0001   ; Побитовое маскирование флагов
MSP.ld  $freg, 0x0000   ; Глухая настройка FREG
MSP.ld  $ptreg, 0x00010000 ; Непосредственный 32-битный адрес в PTREG
MSP.ld  $ptreg, [0xA000]; Чтение указателя из памяти MEM[0xA000] в PTREG
MSP.ld  $ptreg, [$0:$1] ; Сборка 32-битного поинтера PTREG = ($0 << 16) | $1 из пары [$0:$1]
MSP.ld  $sreg, [$0:$1]  ; Сборка указателя стека SREG из пары [$0:$1]
MSP.ld  $sreg, 0x00003F00 ; Установка вершины стека SREG (непосредственное значение)

; Векторы прерываний ($ir0..$ir15), Зоны Привилегий ($pv0..$pv13) и границы ROM ($pv14..$pv15):
MSP.ld  $ir0, 0x00010000 ; Установка вектора прерывания IRQ0 (32-битный адрес)
MSP.ld  $ir1, [$0:$1]    ; Установка вектора прерывания IRQ1 из составного поинтера [$0:$1]
MSP.ld  $pv0, 0x00008000 ; Нижняя граница Зоны Привилегий 0
MSP.ld  $pv1, 0x00008FFF ; Верхняя граница Зоны Привилегий 0
MSP.ld  $rom_base, 0x00000000  ; Нижняя граница постоянной памяти ROM ($pv14)
MSP.ld  $rom_limit, 0x00003FFF ; Верхняя граница постоянной памяти ROM ($pv15)

; Нативное многократное разыменование цепочки указателей:
MSP.ld  $ptreg, 0xA000  ; Корень
MSP.ld  $ptreg, [$ptreg]; 1-е разыменование: PTREG = *0xA000
MSP.ld  $ptreg, [$ptreg]; 2-е разыменование: PTREG = **0xA000
LMR.w   $0, [$ptreg]    ; Чтение финальных данных
```

### 6. Переходы и вызовы подпрограмм (`JMP`, `JCR`, `JNZ`, `JZ`, `CALL`)
Все инструкции переходов и вызовов строго соответствуют 32-битной адресной шине и оперируют полными 32-битными адресами:
* **Прямой переход по адресу/метке (`MOD=0`, 5 байт):**
  ```asm
  JMP loop_start        ; Безусловный 32-битный переход на адрес метки loop_start
  JMP 0x100000          ; Прямой дальний переход в ОЗУ (32 бита Little-Endian)
  CALL my_subroutine    ; Вызов подпрограммы с сохранением 32-битного PC и FREG в стек SREG
  JZ  is_zero           ; Переход, если флаг ZF == 1
  JNZ not_zero          ; Переход, если флаг ZF == 0
  ```
* **Косвенный переход по ссылке в памяти (`MOD=3`, 5 байт):**
  ```asm
  JMP [func_ptr]        ; Переход по 32-битному адресу, прочитанному из ячейки памяти func_ptr
  CALL [vtable_slot]    ; Косвенный вызов через 32-битную ячейку в памяти
  ```
* **Регистровый переход (`MOD=1`, 2 байта):** `JMP $0` / `CALL $0`
* **Переход по указателю PTREG (`MOD=2`, 2 байта):** `JMP [$ptreg]` / `JMP $ptreg`

* **Условный переход по результату сравнения `JCR` (Jump Compare Result, Opcode 10):**
  Проверяет результат аппаратного сравнения в битах `6–7` флагового регистра `FREG` (`01`: `<`, `10`: `==`, `11`: `>`).
  Поле конфигурации `CFG [2:0]` в 1-м байте инструкции:
  - Бит 2: `INV` (`0` = условие совпадает, `1` = инверсия/не совпадает)
  - Биты `1–0`: ожидаемый код сравнения (`01` = `<`, `10` = `==`, `11` = `>`)
  - Комбинации условий: `<` (`001`), `==` (`010`), `>` (`011`), `>=` (`101`), `!=` (`110`), `<=` (`111`).
  - Целевой адрес перехода `target32` занимает полные **4 байта Little-Endian** (32 бита).

  Поддерживается **два варианта синтаксиса**:
  1. **Упрощенный составной макрос (7 байт):**
     ```asm
     JCR $1 > $2, loop_target   ; Автоматически разворачивается в:
                                ; 1) CMP $1, $2 (2 байта)
                                ; 2) JCR >, loop_target (5 байт)
     JCR $3 <= $4, exit_label
     ```
  2. **Ручной синтаксис (5 байт):**
     ```asm
     CMP $0, $1
     JCR <, on_less             ; Переход, если $0 < $1 (5 байт)
     JCR ==, on_equal           ; Переход, если $0 == $1 (5 байт)
     JCR >, on_greater          ; Переход, если $0 > $1 (5 байт)
     JCR >=, on_ge              ; Переход, если $0 >= $1 (5 байт)
     JCR !=, on_ne              ; Переход, если $0 != $1 (5 байт)
     JCR <=, on_le              ; Переход, если $0 <= $1 (5 байт)
     ; Также поддерживается точечная форма:
     JCR.GT on_greater
     JCR.EQ on_equal
     ```

### 7. Символы адресации и счетчика команд
* `$` — Текущий адрес команды / текущий location counter (Program Counter). Не конфликтует с регистрами `$0`..`$7`.
  ```asm
  msg: db "HELLO"
  msg_len = $ - msg     ; Вычисление длины буфера
  ```
* `$$` — Базовый адрес текущей программы или текущей секции `.org`.
* `.` — Синоним `$`.
* `__LINE__` — Текущий номер строки в исходнике.

### 8. Директивы данных (Порядок байт: Little-Endian)
Инструкции в памяти хранятся в формате Big-Endian (старшие биты первыми). Данные в памяти размещаются в формате **Little-Endian** (младший байт по младшему адресу):

* **`db`** (`.byte`) — 1 голый байт (или строка): `db 0x42`, `db "LIM2", 0`
* **`dw`** (`.word`) — 2 голых байта (16 бит, Little-Endian): `dw 0x1234` $\to$ `[0x34, 0x12]`
* **`dp`** (`.ptr`, `dt`) — **3-байтный указатель** (24 бита, Little-Endian) для экономии памяти адресации: `dp 0x018000` $\to$ `[0x00, 0x80, 0x01]` (вместо 4 байт тратит ровно 3 байта!)
* **`dd`** (`.dword`) — 4 голых байта (32 бита, Little-Endian): `dd 0x12345678` $\to$ `[0x78, 0x56, 0x34, 0x12]`
