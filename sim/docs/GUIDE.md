# Полное руководство по архитектуре и симулятору LIM2

Исчерпывающее техническое руководство по низкоуровневой платформе симулятора процессора, шины и периферийных устройств **LIM2** (Pure Python).

---

## 1. Философия и архитектурная модель

Симулятор **LIM2** спроектирован так, чтобы дать разработчику абсолютный контроль над каждым транзистором, регистром, шиной и ножкой без использования тяжелых внешних библиотек и скрытой магии:
1. **100% Чистый Python (Zero Dependencies):** Никаких внешних библиотек (C-биндингов, сторонних движков). Весь код можно открыть, понять и модифицировать.
2. **Конфигурация платформы прямо в коде (`sim.py`):** Вся материнская плата, распределение адресов (Memory Map), мониторы и контроллеры объявляются в коде на Python. Больше **не нужно вводить длинные флаги командной строки** (`-m`, `-v`) при каждом запуске!
3. **Честная симуляция сигнальных линий (Pins):** Линии управления (`RD`, `WR`, `MREQ`, `IORQ`, `CS`, `IRQ`, `RF`) и любые произвольные ножки симулируются с поддержкой стробов и коллбэков.
4. **Аппаратное отставание памяти (Latency & Wait States):** Возможность задавать задержку выборки ячеек памяти в тактах шины и отрабатывать протокол готовности данных через ножку `RF` (Ready Flag).
5. **Превосходный TUI-интерфейс:** Многоколоночная адаптивная визуализация процессора в виде микросхем, окон памяти устройств, текстовых видеомониторов и карты адресного пространства в стиле *diskmgmt.msc*.

---

### Поддерживаемые форматы файлов программ:
Симулятор автоматически распознает формат по расширению:
- `.bin` — сырой бинарный исполняемый код процессора (Firmware / Kernel binary image).
- `.hex` — текстовые шестнадцатеричные файлы или формат Intel HEX (`:100000...`).
- `.asm` / `.lasm` — ассемблерные листинги с автоматической трансляцией в машинный код на лету.

### Режимы запуска симулятора:

Симулятор LIM2 предоставляет два полноценных окружения: современный оконный графический интерфейс (**GUI** на Tkinter) и интерактивный терминальный интерфейс (**TUI**):

```bash
cd LIM2/sim

# 1. Запуск современного графического интерфейса (GUI):
python3 sim.py demo.hex
python3 sim.py demo.asm

# 2. Запуск интерактивного терминального отладчика (TUI):
python3 sim.py demo.hex -i
python3 sim.py kernel.bin -i
```
Симулятор автоматически запустится со всеми устройствами, настроенными в коде `sim.py`.

### Режим долговременной работы (Long-Term Work, `-L`):
Флаг `-L` (или `--long-term [DUMP_FILE]`) переводит симулятор в режим непрерывной сессии:
```bash
# Использование дампа по умолчанию (lim2_state.dump):
python3 sim.py demo.bin -i -L

# Или с указанием собственного файла снимка:
python3 sim.py demo.bin -i -L my_system.dump
```
- **При старте:** если файл дампа существует, симулятор бесшовно восстанавливает полное состояние машины: счетчик команд `PC`, регистры, флаги, ОЗУ и видеопамять.
- **При выходе (Ctrl+C или 'q'):** симулятор автоматически сохраняет снимок всей машины обратно в дамп!

### Пакетный запуск (Batch Mode):
```bash
python3 sim.py demo.bin -n 1000
```

## 3. Анатомия процессора: Построчный разбор (`cpu.py` / `lim2_cpu.py`)

Процессор наследуется от базового класса `BaseCPU` ([`core.py`](../core.py)) и состоит из 3 ключевых методов:
- `setup(self)` — объявление регистрового файла, разрядности, ролей и флагов.
- `on_start(self)` — начальное состояние при включении питания или аппаратном сбросе (`reset`).
- `on_step(self)` — пошаговая выборка инструкций, парсинг битов и исполнение команд.

---

### 3.1. Создание регистров (`setup`)

Каждый регистр объявляется вызовом метода `self.reg(...)` (или `self.compact_reg(...)` для компактного отображения векторов в одну строку):

```python
def setup(self):
    # 1. Регистры общего назначения (16 бит каждый, R0..R7)
    for i in range(8):
        self.reg(
            name=f"r{i}",      # Системное имя регистра (доступно как self.r0, self.r1)
            bits=16,           # Разрядность в битах (маска 0xFFFF)
            default=0,         # Значение при старте и сбросе
            indexed=True,      # Доступ по номеру: self.get_reg(i), self.set_reg(i, val)
            title=f"R{i}",     # Текстовая подпись на панели в GUI и TUI
            role="General",    # Роль регистра
            block="core"       # Блок процессора
        )

    # 2. Служебные аккумуляторы АЛУ (16 бит каждый)
    self.reg("acca", bits=16, default=0, title="ACCA", is_acc=True, is_aux=True, block="ALU")
    self.reg("accb", bits=16, default=0, title="ACCB", is_acc=True, is_aux=True, block="ALU")

    # 3. Системный 32-битный указатель стека SREG (адресация 4 ГБ)
    self.reg("sreg", bits=32, default=0, aliases=["sp"], title="SREG", role="Stack 32b", block="SYS")

    # 4. Расширенный 32-битный регистр указателя PTREG (адресация 4 ГБ)
    self.reg("ptreg", bits=32, default=0, title="PTREG", role="Pointer 32b", block="ADDR")

    # 5. Таблица 16 векторов аппаратных прерываний (IR0..IR15, 32 бита каждый)
    for i in range(16):
        self.compact_reg(f"ir{i}", bits=32, default=0, title=f"IR{i}", role="Interrupt Vector 32b", block="IVT")

    # 6. Зоны защиты привилегий (PV0..PV13, 7 пар) и границы ROM (PV14..PV15, 1 пара)
    for i in range(14):
        self.compact_reg(f"pv{i}", bits=32, default=0, title=f"PV{i}", role="Privilege Zone 32b", block="PROT")
    self.compact_reg("pv14", bits=32, default=0, title="PV14", role="ROM Base 32b", block="PROT")
    self.compact_reg("pv15", bits=32, default=0, title="PV15", role="ROM Limit 32b", block="PROT")

    # 7. Физические ножки процессора (PINS)
    self.pin("RD", mode="OUT", title="Read Strobe")
    self.pin("WR", mode="OUT", title="Write Strobe")
    self.pin("MREQ", mode="OUT", title="Memory Request")
    self.pin("IORQ", mode="OUT", title="I/O Request")
    self.pin("IRQ", mode="IN", title="Interrupt Request")
    self.pin("IA", mode="OUT", title="Interrupt Acknowledge")
    self.pin("HALT", mode="OUT", title="Halt Output")
    self.pin("RESET", mode="IN", title="Reset Input")
    self.pin("RF", mode="IN", title="Ready Flag")
```

#### Что делает каждый параметр:
1. `name`: Строковое имя регистра. Создает динамический доступ: `cpu.r0 = 0x42` или `val = cpu.r0`.
2. `bits`: Разрядность регистра в битах. Внутри вычисляется маска `mask = (1 << bits) - 1`. Для 16-битных регистров это `0xFFFF`, а для 32-битных (`PC`, `PTREG`, `SREG`, `IR0..15`, `PV0..15`) — `0xFFFFFFFF`. Любое значение автоматически ограничивается разрядной маской без риска переполнения Python!
3. `default`: Начальное значение при подаче питания и вызове аппаратного сброса `cpu.reset()`.
4. `indexed=True`: Позволяет обращаться к регистрам по целочисленному индексу: `self.get_reg(0)` и `self.set_reg(0, val)`. Когда номер регистра декодируется из битов инструкции (`rd = 3`), вызывается `self.set_reg(rd, result)`.
5. `compact_reg(...)`: Специальный режим регистрации, отображающий регистр в интерфейсе компактной текстовой строкой, экономящей место для 32 векторных регистров.
6. `self.pin(name, mode="IN"|"OUT", title=...)`: Декларирует физическую ножку процессора прямо в классе CPU. Позволяет обращаться к ножкам напрямую через `self.pins.IA.set(1)` или `self.pins.IRQ.get()`.

#### 3.2. Как устроен Program Counter (Счетчик команд, PC, 32 бита)

Счетчик команд в архитектуре LIM2 является **нативным 32-битным регистром**:
```python
self.reg("pc", bits=32, default=0x00000000, is_pc=True, title="PC")
```

#### Ручная работа с Program Counter (`self.pc += 1`):
В симуляторе LIM2 вы имеете абсолютный ручной контроль над программным счетчиком:
* **Чтение текущего адреса:** `self.pc` (значение в диапазоне `0x00000000..0xFFFFFFFF`).
* **Прямой ручной инкремент счетчика:**
  ```python
  self.pc += 1    # переход к следующему байту команды
  self.pc += 2    # пропуск слова
  self.pc += 4    # пропуск 32-битного непосредственного адреса
  ```
* **Чтение байта из шины по PC:**
  ```python
  byte = self.bus.read8(self.pc)
  self.pc += 1
  ```
* **Прямые и относительные переходы (Jumps):**
  - Безусловный 32-битный переход: `self.pc = target_addr & 0xFFFFFFFF`
  - Относительный переход: `self.pc = (self.pc + offset) & 0xFFFFFFFF`
  - Условный переход:
    ```python
    if self.get_flag("ZF") == 1:
        self.pc = target_addr
    ```

### 3.3. Создание и управление флагами (`FREG`)

Регистр флагов `FREG` (16 бит) объявлен с флагом `is_flag=True` и детальной картой битов `flag_layout`:

```python
flag_layout = [
    ("ZF", "Zero", 0),          # Бит 0: Флаг нуля (Zero Flag)
    ("CF", "Carry", 1),         # Бит 1: Флаг переноса / заёма (Carry / Borrow)
    ("OF", "Overflow", 2),      # Бит 2: Флаг знакового переполнения
    ("EM", "ErrMath", 3),       # Бит 3: Математическая ошибка (деление на ноль)
    ("CMP0", "CmpBit0", 4),     # Бит 4: Младший бит результата аппаратного компаратора
    ("CMP1", "CmpBit1", 5),     # Бит 5: Старший бит результата аппаратного компаратора
    ("PIE", "ProgInt", 8),      # Бит 8: Разрешение программных прерываний
    ("MIE", "MasterInt", 9),    # Бит 9: Глобальное разрешение прерываний
    ("DWR", "NoWait", 10),      # Бит 10: Отключение ожидания готовности шины (DWR)
    ("PRV", "Superv", 11),      # Бит 11: 0=User Mode, 1=Supervisor Mode (защищен 8 зонами)
    ("AIP", "AutoInc", 12),     # Бит 12: Аппаратный автоинкремент PTREG при обращении к памяти
    ("DBIT", "DispBit", 13),    # Бит 13: Буфер вытесненного бита сдвигового регистра
    ("SMOD", "ShiftMod", 14),   # Бит 14: Режим сдвига (0=заполнение нулями, 1=через DBIT)
    ("INTR", "InIntr", 15),     # Бит 15: Флаг нахождения в обработчике прерывания
]
self.reg("freg", bits=16, default=0x0800, is_flag=True, flag_layout=flag_layout, title="FREG")
```

#### Как проверять и изменять флаги:
1. **По именам флагов (рекомендуемый способ):**
   ```python
   # Установить флаг нуля:
   self.set_flag("ZF", 1)

   # Сбросить флаг переноса:
   self.set_flag("CF", 0)

   # Проверить флаг в условии перехода:
   if self.get_flag("ZF") == 1:
       self.pc = target_addr
   ```
2. **Через битовые маски напрямую:**
   ```python
   # ZF находится в бите 0:
   is_zero = (result & 0xFFFF) == 0
   self.freg = (self.freg & ~0x01) | (1 if is_zero else 0)
   ```
В графическом интерфейсе каждый бит регистра флагов отображается отдельным интерактивным индикатором `[ZF:1]`, `[CF:0]`.

### 3.4. Выборка, ручной инкремент PC и битовый парсер (`on_step`)

В методе `on_step()` все низкоуровневые действия вы пишете вручную:

```python
def on_step(self):
    # 1. Пошаговая выборка двух 8-битных байтов (char) с РУЧНЫМ инкрементом PC:
    b0 = self.bus.read8(self.pc)
    self.pc += 1

    b1 = self.bus.read8(self.pc)
    self.pc += 1

    # 2. Вручную склеиваем два байта на шине данных (databus) в 16-битную инструкцию:
    self.databus = (b0 << 8) | b1

    # 3. Декодируем поля с помощью конструктора парсинга бит:
    opcode, cfg, rd, rs1, rs2 = self.parse("[15-11] [10-8] [7-5] [4-2] [1-0]")
```
```

#### Как работает шаблон `parse(...)`:
* `[15-11]` — извлекает диапазон битов 15..11 (5 бит, число от 0 до 31).
* `[15]` — **парсинг ровно 1 бита**: извлекает бит 15 (значение 0 или 1).
* `[sign:15] [exp:14-10]` — поддержка необязательных меток полей для наглядности.

#### Примеры гибкого использования `self.parse`:
1. **Парсинг одного поля в переменную (число int):**
   ```python
   opcode = self.parse("[15-11]")
   if opcode == 1:
       print("Это команда ADD")
   ```
   > [!NOTE]
   > При парсинге одиночного диапазона результат ведет себя как обычное число `int`: его можно сравнивать (`opcode == 1`, `opcode < 10`), складывать (`opcode + 1`), форматировать (`f"0x{opcode:02X}"`) и использовать как индекс. При этом сохраняется и возможность распаковки через кортеж: `opcode, = self.parse("[15-11]")`.

2. **Парсинг одиночного бита (0 или 1):**
   ```python
   is_immediate = self.parse("[15]")  # 15-й бит (0 или 1)
   if is_immediate:
       # обработка флага
       pass
   ```

3. **Смешанный парсинг (одиночные биты + диапазоны):**
   ```python
   # 1 бит флага + 3 бита режима + 4 бита регистра:
   has_imm, mode, reg = self.parse("[15] [14-12] [11-8]")
   ```

4. **Парсинг из произвольной переменной (не только databus):**
   ```python
   high_nibble, low_nibble = self.parse("[7-4] [3-0]", value=my_byte)
   ```

#### Логика опкодов на чистом Python:
```python
    if opcode == 0:
        # NOP — нет операции; сбрасывает ALU_RESIDUAL и флаги каскадной цепочки
        self.alu_residual = 0

    elif opcode == 1:
        # ADD Rd, Rs1, Rs2 (Трёхоперандное сложение с автокаскадированием)
        val1 = self.get_reg(rs1)
        val2 = self.get_reg(rs2)
        carry_in = 1 if self.get_flag("CF") else 0
        raw_sum = val1 + val2 + carry_in
        res = raw_sum & 0xFFFF
        self.set_reg(rd, res)
        self.set_flag("ZF", 1 if res == 0 else 0)
        self.set_flag("CF", 1 if raw_sum > 0xFFFF else 0)
        self.alu_residual = (raw_sum >> 16) & 0xFFFF

    elif opcode == 5:
        # LMR Rd, <SRC_MODE> (Загрузка из 32-битного адресного пространства в регистр)
        # Поддерживаются режимы: 0=Immediate константа, 1=Immediate указатель [addr32],
        # 2=Косвенно через 32-битный PTREG (с опциональным автоинкрементом AIP),
        # 3=Составная 32-битная регистровая пара [$rd:$rs]
        val = self._resolve_lmr_value(mode, size_flag)
        self.set_reg(rd, val)

    elif opcode == 6:
        # LRM Rs, <DST_MODE> (Выгрузка регистра в память по 32-битному адресу)
        addr = self._resolve_lrm_address(mode)
        self.bus.write16(addr, self.get_reg(rs))

    elif opcode == 7:
        # LRR Rd, Rs (Быстрое межрегистровое копирование через байпас MUX 1 -> MUX 2)
        self.set_reg(rd, self.get_reg(rs))

    elif opcode == 8:
        # CMP Rs1, Rs2 (Аппаратный компаратор: 01=меньше, 10=равно, 11=больше)
        v1, v2 = self.get_reg(rs1), self.get_reg(rs2)
        cmp_code = 0b01 if v1 < v2 else (0b10 if v1 == v2 else 0b11)
        self.set_flag("CMP0", cmp_code & 1)
        self.set_flag("CMP1", (cmp_code >> 1) & 1)

    elif opcode == 22:
        # PUSH Rs (Запись 16-битного слова в 32-битный стек)
        self.sreg = (self.sreg - 2) & 0xFFFFFFFF
        self.bus.write16(self.sreg, self.get_reg(rs))

    elif opcode == 23:
        # POP Rd (Извлечение 16-битного слова из 32-битного стека)
        self.set_reg(rd, self.bus.read16(self.sreg))
        self.sreg = (self.sreg + 2) & 0xFFFFFFFF

    elif opcode == 26:
        # MSP: работа со спецрегистрами FREG (00), PTREG 32b (01), SREG 32b (10), VEC 32b (11)
        act, sreg_sel = self.parse("[10] [9-8]")
        if sreg_sel == 1:  # PTREG (32 бита)
            if act == 0:   # Загрузка
                self.ptreg = target_addr32 & 0xFFFFFFFF
            else:          # Арифметика (ADD/SUB)
                self.ptreg = (self.ptreg + offset if op == 0 else self.ptreg - offset) & 0xFFFFFFFF
        elif sreg_sel == 2:  # SREG (32 бита)
            if act == 0:
                self.sreg = target_addr32 & 0xFFFFFFFF
            else:
                self.sreg = (self.sreg + offset if op == 0 else self.sreg - offset) & 0xFFFFFFFF
        elif sreg_sel == 3:  # 32 векторных регистра (0..15: IR0..15, 16..31: PV0..15)
            self.vectors[vec_id] = target_addr32 & 0xFFFFFFFF

    elif opcode == 28:
        # INTR vec4 (Программное прерывание: выбор вектора 0..15 из $ir0..$ir15)
        # Работает аналогично CALL: сохраняет PC и FREG, переходит на адрес вектора.
        vec_id = self.databus & 0x0F
        # 1. Сохраняем 32-битный PC возврата в стек SREG
        self.sreg = (self.sreg - 4) & 0xFFFFFFFF
        self.bus.write32(self.sreg, self.pc)
        # 2. Сохраняем 16-битный FREG
        self.sreg = (self.sreg - 2) & 0xFFFFFFFF
        self.bus.write16(self.sreg, self.freg)
        # 3. Переход на 32-битный адрес обработчика из таблицы векторов
        # Режим супервизора программа включает сама по необходимости (через MSP.or $freg, PRV)
        self.pc = self.vectors[vec_id] & 0xFFFFFFFF

    elif opcode == 29:
        # CALL (Вызов подпрограммы с автоматическим сохранением 32-битного PC и 16-битного FREG)
        ret_addr = self.pc & 0xFFFFFFFF
        self.sreg = (self.sreg - 4) & 0xFFFFFFFF
        self.bus.write32(self.sreg, ret_addr)
        self.sreg = (self.sreg - 2) & 0xFFFFFFFF
        self.bus.write16(self.sreg, self.freg & 0xFFFF)
        self.pc = target_addr32 & 0xFFFFFFFF

    elif opcode == 30:
        # RET (Универсальный симметричный возврат из подпрограммы и прерывания)
        # Автоматически восстанавливает 16-битный FREG и 32-битный PC из стека SREG
        self.freg = self.bus.read16(self.sreg) & 0xFFFF
        self.sreg = (self.sreg + 2) & 0xFFFFFFFF
        self.pc = self.bus.read32(self.sreg) & 0xFFFFFFFF
        self.sreg = (self.sreg + 4) & 0xFFFFFFFF

    elif opcode == 31:
        # HALT — останов процессора
        self.halt()
```

## 4. Конфигурация платформы и устройств в коде (`sim.py`)

Все устройства материнской платы объявляются в функции `setup_platform(bus)` внутри файла [`sim.py`](../sim.py). Шина `MemoryBus` работает в **нативном 32-битном адресном пространстве** (`0x00000000..0xFFFFFFFF`, 4 ГБ) с автоматическим контролем конфликтов шины (Bus Contention):

```python
from bus import MemoryBus
from devices import (
    RAMDevice, ROMDevice,
    TextScreen,       # Текстовый CRT терминал (псевдоним TextScreenDevice)
    Display256,       # 8-битный графический дисплей (256 цветов, 3-2-3 / 3-3-2)
    Display16M,       # 24-битный TrueColor дисплей (16.7 млн цветов)
    PixelScreen,      # Пиксельный монитор высокой четкости
    UART,             # Последовательный порт UART (псевдоним UARTDevice)
    TimerDevice       # Аппаратный таймер
)

def setup_platform(bus: MemoryBus):
    # 1. Системное ОЗУ (0x00000000 .. 0x000FFFFF = 1 Мегабайт)
    bus.attach(RAMDevice(start=0x00000000, end=0x000FFFFF, name="RAM"))

    # 2. Текстовый видеомонитор CRT 20x4 с предустановленным текстом:
    bus.attach(TextScreen(
        start=0x00010000,
        width=20,
        height=4,
        name="MONITOR",
        default_data="LIM2 SYSTEM READY..."  # Текст сразу появится на экране!
    ))

    # 3. 256-цветовой графический дисплей 64x64 (8 бит на пиксель, RGB 3-2-3):
    bus.attach(Display256(
        start=0x00020000,
        width=64,
        height=64,
        name="GPU_256"
    ))

    # 4. Последовательный порт UART (0x00030000 .. 0x00030003)
    bus.attach(UART(start=0x00030000, name="UART0"))

    # 5. Аппаратный таймер (0x00030010 .. 0x00030013)
    bus.attach(TimerDevice(start=0x00030010, name="TIMER0", irq_pin="IRQ"))
```

### Предварительная инициализация устройств (`default_data` и `default_offset`)
При создании любого устройства (`RAMDevice`, `ROMDevice`, `TextScreen`, `create_dev`) можно сразу заполнить его начальными данными. Поддерживаются любые типы данных:
- **ASCII строка:** `default_data="HELLO CPU!"` — кодируется в байты символов.
- **Шестнадцатеричная строка:** `default_data="AA BB CC 01 02 03"` или `"0xAA 0xBB 0xCC"`.
- **Список чисел / байты:** `default_data=[0x12, 0x34]` или `default_data=bytes([0x55, 0xAA])`.
- **Путь к файлу прошивки:** `default_data="boot.bin"` — файл автоматически прочитается с диска.
- **Смещение `default_offset`:** адрес внутри устройства, с которого начинается запись данных (по умолчанию `0`).

Каждое устройство занимает непрерывный диапазон адресов `[start .. end]` и сразу же отображается на карте памяти:
```text
┌── [КАРТА АДРЕСНОГО ПРОСТРАНСТВА ШИНЫ (32 бит, 4 ГБ)] ────────────────────────┐
│ РАСПРЕДЕЛЕНИЕ ПАМЯТИ УСТРОЙСТВ (DISKMGMT.MSC STYLE):                         │
│ ┌───────────────┬────────────────┬────┬────────────────┬────┬────┬────┬────┐ │
│ │      RAM      │   [Свободно]   │MONI│   [Свободно]   │UART│ ░░ │TIME│ ░░ │ │
│ ├───────────────┼────────────────┼────┼────────────────┼────┼────┼────┼────┤ │
│ │0x000000..FFFF │ 0x010000..     │1000│ 0x010050..     │3000│    │3010│    │ │
│ │  1 МБ         │                │ 0% │                │ 0% │    │ 0% │    │ │
│ └───────────────┴────────────────┴────┴────────────────┴────┴────┴────┴────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 5. Как связать устройства друг с другом и с процессором

Взаимодействие компонентов в симуляторе LIM2 строится по двум аппаратным принципам:
1. **Memory-Mapped I/O (MMIO):** Обращение через 32-битную шину адреса и 8-битную шину данных.
2. **Сигнальные ножки (Pins & Signals):** Аппаратные стробы и прерывания.

### Способ 1: Общение процессора с устройством через MMIO
Когда процессор выполняет команду записи:
```python
self.bus.write8(0x00010000, ord('A'))
```
1. Шина `MemoryBus` проверяет 32-битный адрес `0x00010000`.
2. Находит устройство `MONITOR` (диапазон `0x00010000..0x0001004F`).
3. Вызывает метод `device.write(offset=0, value=65)`.
4. Символ `'A'` немедленно отображается в видеопамяти и на экране монитора.
5. Автоматически инкрементируется `_vram_version` для мгновенного обновления GUI без тормозов.

### Способ 2: Прерывания от таймера к процессору через ножку IRQ
1. В таймере `TIMER0` на каждом такте уменьшается счетчик.
2. Когда счетчик равен 0, таймер поднимает сигнал на ножке шины:
   ```python
   self.bus.pins.IRQ.set(1)
   ```
3. Процессор в начале метода `on_step()` обрабатывает прерывание:
   ```python
   if self.bus.pins.IRQ.get() == 1 and self.get_flag("MIE"):
       self.trigger_irq(vector_num=0)
       self.bus.pins.IRQ.set(0)  # Сбрасываем сигнал прерывания
   ```

### Способ 3: Прямая связь устройств через слушатели ножек (`listen`)
Одно устройство может напрямую подписаться на изменение сигнала другого:
```python
# Устройство Б слушает сигнал ACK от устройства А:
bus.pins.DEV_A_ACK.listen(lambda val: print(f"Устройство Б получило сигнал: {val}"))
```

### Способ 4: Аппаратный контроль конфликтов шины (Bus Contention)
Если два устройства случайно сконфигурированы с пересекающимися диапазонами адресов и пытаются одновременно выдать данные на шину:
```python
bus.on_collision = lambda msg: print(f"[ПРЕДУПРЕЖДЕНИЕ ШИНЫ] {msg}")
```
Шина немедленно детектирует коллизию и предупреждает разработчика в логе и строке состояния GUI.

## 6. Поддержка ножек, отставание памяти (Latency) и рукопожатие (RF Handshake)

В реальном железе микросхемы памяти (ROM, DRAM) не отдают данные мгновенно — им требуется время доступа (Access Time / Wait States). В LIM2 это полностью симулируется!

### 6.1. Настройка задержки памяти
Задержка задается параметром `latency` (число тактов шины) и ножкой готовности `ready_pin` (по умолчанию `RF` — Ready Flag):

```python
# Память с задержкой в 2 такта шины:
ram = RAMDevice(start=0x0000, end=0x3FFF, latency=2, ready_pin="RF")
bus.attach(ram)

# Или через метод set_latency:
ram.set_latency(cycles=3, ready_pin="RF")
```

### 6.2. Временная диаграмма цикла шины (Bus Cycle Handshake)

```text
ТАКТ 1 (Start Read):    CPU: ADDR=0x1000, RD=1  -->  RAM: видит RD, сбрасывает RF=0 (BUSY)
ТАКТ 2 (Wait State T1): CPU: видит RF=0 (ждет)  -->  RAM: отсчитывает задержку (остался 1 такт)
ТАКТ 3 (Wait State T2): CPU: видит RF=0 (ждет)  -->  RAM: отсчитала задержку, ставит RF=1 (READY)
ТАКТ 4 (Data Capture):  CPU: видит RF=1, считывает данные DATA, сбрасывает RD=0
```

### 6.3. Как использовать в коде:

#### Вариант А: Автоматическое рукопожатие через `bus.read_handshake`
```python
# Процессор делает запрос, шина отрабатывает такты ожидания и возвращает данные:
data, wait_cycles = self.bus.read_handshake(0x1000)
print(f"Прочитан байт 0x{data:02X}, память задержала процессор на {wait_cycles} тактов.")
```

#### Вариант Б: Пошаговая симуляция ножек вручную
```python
# 1. Процессор выставляет сигнал чтения:
self.bus.pins.RD.set(1)
ram.start_read(offset=0x10)

# В этот момент ножка RF равна 0!
assert self.bus.pins.RF.get() == 0

# 2. Процессор крутится в цикле ожидания (Wait States):
waited_cycles = self.wait_for_pin("RF")

# 3. Ножка RF стала равной 1! Считываем данные и снимаем строб RD:
data = self.bus.read8(0x1010)
self.bus.pins.RD.set(0)
```

## 7. Разработка собственных внешних устройств (`devices.py`)

Для создания любого периферийного модуля унаследуйте класс `BaseDevice`:

```python
from devices import BaseDevice

class MyCustomDevice(BaseDevice):
    def __init__(self, start: int, size: int = 16, name: str = "MY_DEV"):
        # Задаем базовый адрес и размер области памяти
        super().__init__(start=start, size=size, name=name)
        self.state = 0

    def read(self, offset: int) -> int:
        """Чтение байта процессором (offset от 0 до size-1)."""
        if offset == 0:
            return self.state
        return self._raw[offset]

    def write(self, offset: int, value: int):
        """Запись байта процессором."""
        val8 = value & 0xFF
        if offset == 0:
            self.state = val8
            # Пример: генерация сигнала на ножке шины
            if self.bus is not None:
                self.bus.pins.IRQ.pulse()
        else:
            self._raw[offset] = val8

    def on_step(self):
        """Вызывается на каждом такте выполнения процессора."""
        pass

    def render_panel(self) -> str:
        """Опциональный графический ASCII-виджет прямо в дашборде."""
        return f"┌── [{self.name}] ──┐\n│ STATE: 0x{self.state:02X} │\n└───{'─'*len(self.name)}──┘"
```

## 8. Графический оконный интерфейс симулятора (GUI) и встроенные дисплеи

В симулятор LIM2 встроен современный десктопный интерфейс на базе **Tkinter GUI** ([`gui.py`](../gui.py)), объединяющий отладку регистров, дизассемблер, дамп памяти и встроенные видеомониторы в одном адаптивном окне.

### Запуск GUI симулятора:
```bash
# Запуск с файлом прошивки:
python3 sim.py demo.asm
python3 sim.py demo.hex
```

### Ключевые возможности интерфейса GUI:

1. **Встроенная мультимониторная подсистема (Embedded Monitors):**
   Больше нет необходимости открывать отдельные окна ОС для каждого дисплея! Прямо в главном окне под панелью памяти расположен блок **«МОНИТОР / ТЕРМИНАЛ ВЫВОДА»** с выпадающим списком выбора активного устройства:
   - **CRT TERMINAL (`TextScreen` / `TextScreenDevice`):** Текстовый экран (например, 20x4 или 80x25), где каждый байт видеопамяти отображает ASCII-символ.
   - **UART SERIAL LOG (`UART` / `UARTDevice`):** Лог последовательного терминала с автопрокруткой и историей переданных символов TX.
   - **256-COLOR PIXEL VRAM (`Display256` / `Display8bppDevice`):** 8-битный графический дисплей (RGB 3-2-3 или 3-3-2) с автоматическим целочисленным масштабированием (`1x`..`8x`).
   - **16.7M TRUECOLOR VRAM (`Display16M` / `Display24bppDevice`):** 24-битный полноцветный экран высокой четкости.
   - **PIXEL MONITOR (`PixelScreen` / `PixelMonitorDevice`):** Графический дисплей с палитрой CGA/EGA.

2. **Интерактивный дамп памяти с редактированием байтов по клику (Inline Edit):**
   Панель памяти компактно отображает окно в 16 строк (256 байт):
   - Адрес строки, 16 шестнадцатеричных байтов и текстовое ASCII-представление.
   - Подсветка текущего байта под указателем `PC` и измененных ячеек.
   - **Редактирование по клику:** кликните мышью прямо по шестнадцатеричному байту в таблице памяти, чтобы открыть удобный inline-инпут и на лету изменить значение байта в физической памяти!
   - Кнопки быстрой навигации: переход по произвольному адресу (`0x...`), листание страниц (`-128`, `+128`).

3. **Аппаратные прерывания (IRQ):**
   Прерывания работают строго по аппаратной модели — через поднятие ножки `IRQ` на панели сигналов или сигналом от аппаратных контроллеров (таймер, UART).

4. **Глобальная поддержка колесика мыши и тачпада:**
   Все секции окна (микросхемы регистров, поток кода дизассемблера, память, терминал) поддерживают плавную прокрутку колесиком мыши и жестами тачпада на macOS, Linux и Windows.

5. **Оптимизация производительности (Zero Memory Leak & 30 FPS Throttle):**
   - **Dirty Tracking (`_vram_version`):** Базовый класс `BaseDevice` и методы записи инкрементируют версию видеопамяти. Если процессор занят внутренними вычислениями и не пишет в VRAM, проверка пропускает перерисовку всего за **0.008 мс**.
   - **In-place масштабирование в C:** Картинка масштабируется в постоянный буфер `PhotoImage` через прямой C-вызов `copy -zoom`. Устранена утечка тысяч дескрипторов изображений в Tcl/Tk, память симулятора абсолютно стабильна при часах непрерывной работы.
   - **Троттлинг непрерывного режима (`Run`):** При запуске на максимальной скорости интерфейс обновляется с фиксированной частотой 30 кадров/сек, позволяя ядру процессора выполнять миллионы тактов без подвисаний GUI.

## 9. Интерактивное меню отладчика (`-i`)

В интерактивном режиме отладчика доступно мощное меню управления:

| Команда | Описание |
|---|---|
| `<Enter>` / `s` / `step` | Выполнить ровно 1 такт/команду |
| `do <N>` | Выполнить `N` тактов (например: `do 20`) |
| `r` / `run` / `cont` | Непрерывный запуск (пауза по `Ctrl+C`) |
| `delay <ms>` | Задержка анимации в миллисекундах (например: `delay 50`) |
| `b <addr>` | Установить или снять точку останова (breakpoint) |
| `r0=0x42` / `r1=100` | Прямое изменение любого регистра |
| `set <addr> <b1> <b2>...` | Запись байтов в память (напр: `set 0x8000 0x48 0x69`) |
| `write <dev> <offset> <val>` | Запись в устройство (напр: `write MONITOR 0 "HELLO"`) |
| `save [file]` | Сохранить полный снимок машины (память, устройства, регистры, PC) в файл |
| `load [file]` | Загрузить полный снимок машины или бинарник прямо в работающий симулятор |
| `layout auto / 1col / 2col / 3col` | Переключение многоколоночного режима |
| `move / cols` | Показать распределение блоков по колонкам и их высоты |
| `move <блок> <1\|2\|3>` | Перенести блок в указанную колонку (напр: `move screen 2`) |
| `move <блок> next / prev` | Сдвинуть блок в следующую/предыдущую колонку (`+` / `-`) |
| `wrap on / off` | Включить/выключить автоперенос блоков при нехватке высоты |
| `height <N\|auto>` | Ограничить максимальную высоту колонки в строках |
| `view cpu / code / mem / screen / map` | Включение / выключение отдельных панелей |
| `reset` | Сбросить процессор в исходное состояние |
| `q` / `quit` / `exit` | Выход из симулятора (с автосохранением дампа, если включен `-L`) |

## 10. Долговременная работа (Long-Term Work, `-L`) и снимки памяти

### Зачем нужен режим `-L`:
При отладке больших программ, операционных систем или длительных вычислений часто необходимо прервать работу симулятора, выключить компьютер, а затем продолжить ровно с того же места, сохранив:
- Все значения регистров общего назначения (`R0`..`R7`, `ACCA`, `ACCB`, `SP` и др.)
- Регистр флагов `FREG`
- Текущий счетчик команд `PC`
- Количество выполненных тактов `step_count`
- Содержимое оперативной памяти (RAM)
- Внутреннее состояние памяти всех внешних устройств (буфер экрана, порты)

### Как использовать флаг `-L`:
```bash
# 1. Первый запуск с прошивкой и автосохранением в дефолтный lim2_state.dump:
python3 sim.py kernel.bin -i -L

# 2. Пошагово работаем, пишем в регистры, меняем экран...
# Выходим из симулятора (команда q или Ctrl+C):
# [LONG-TERM] Состояние симулятора успешно сохранено в 'lim2_state.dump'

# 3. Повторный запуск БЕЗ указания прошивки (симулятор продолжит работу с сохраненной точки!):
python3 sim.py -i -L
# [LONG-TERM] Восстановлено состояние из дампа 'lim2_state.dump' (PC: 0x0124, тактов: 1540)
```

### Именованные дампы:
Можно вести несколько независимых сессий:
```bash
python3 sim.py os.bin -i -L session_boot.dump
python3 sim.py app.bin -i -L session_calc.dump
```

## 11. Настройка колонок и автоперенос по высоте экрана

### 11.1. Доступные инфо-блоки:
Интерфейс симулятора состоит из 5 ключевых модулей:
- `cpu` (регистры процессора, микросхемы, АЛУ, флаги)
- `code` (дизассемблер потока инструкций с подсветкой текущего `PC`)
- `screen` (видеомониторы и текстовые экраны с рамками)
- `mem` (память устройств, шестнадцатеричные дампы с подсветкой изменений)
- `map` (графическая карта шины памяти в стиле *diskmgmt*)

### 11.2. Перемещение любого блока в интерактивном режиме:
Вы можете в любой момент на лету переместить любой блок в нужную колонку:
```text
(cpu) > move screen 2         # переносит видеомонитор во 2-ю колонку
(cpu) > move screen 3         # переносит видеомонитор в 3-ю колонку
(cpu) > move code 1           # переносит дизассемблер в 1-ю колонку
(cpu) > move cpu 2            # переносит регистры во 2-ю колонку
(cpu) > move mem 1            # переносит память в 1-ю колонку
```

Циклический сдвиг:
```text
(cpu) > move screen next      # сдвигает монитор в следующую колонку (1 -> 2 -> 3 -> 1)
(cpu) > move screen prev      # сдвигает монитор в предыдущую колонку (3 -> 2 -> 1 -> 3)
```

Просмотр текущего распределения:
```text
(cpu) > move                  # или команда: cols
```

### 11.3. Автоматический перенос при превышении высоты экрана (Height Auto-Wrap):
Если окно вашего терминала невысокое (например, 24 или 30 строк), вертикальное размещение нескольких блоков (например, микросхемы процессора + видеомонитор) может привести к тому, что экран не поместится и потребуется вертикальная прокрутка.

Симулятор **автоматически отслеживает высоту окна терминала**:
- Если суммарная высота блоков в колонке превышает доступную высоту экрана, лишние блоки **автоматически "перетекают" в соседнюю свободную колонку**!
- Управление автопереносом:
  - `wrap on` — включить умный перенос по высоте (включен по умолчанию).
  - `wrap off` — выключить перенос (блоки жестко фиксируются в заданных колонках).
  - `height <число>` — явно задать ограничение высоты в строках (например `height 20`).
  - `height auto` — вернуть автоматическое определение по размеру терминала.

### 11.4. Настройка колонок и переноса в коде Python (`sim.py`):
```python
from ui import UIConfig
from runner import SimulationRunner

# Задаем желаемое распределение блоков и автоперенос:
cfg = UIConfig(
    layout_mode="auto",
    block_columns={
        "cpu": 1,
        "screen": 2,   # Монитор сразу во 2-й колонке!
        "code": 1,     # Дизассемблер в 1-й колонке
        "mem": 3,
        "map": 3,
    },
    auto_height_wrap=True,  # Включен перенос по высоте
    max_col_height=None     # Адаптивно по высоте окна терминала
)

runner = SimulationRunner(cpu, ui_config=cfg)
runner.run_interactive()
```

## 12. Ассемблер и компилятор LIM M2 ([`limasm.py`](../limasm.py))

В состав симулятора входит двухпроходный компилятор языка ассемблера **`limasm.py`**, который переводит программы на языке ассемблера LIM M2 (`.asm`) в чистый бинарный код (`.bin`) и аннотированный шестнадцатеричный дамп (`.hex`), а также позволяет запускать `.asm` файлы напрямую в `sim.py`.

### 12.1. Именование регистров
Все регистры в языке ассемблера указываются через префикс `$`:
- **`$0` .. `$7`** — 16-битные регистры общего назначения (также поддерживаются классические псевдонимы `R0`..`R7` и `$r0`..`$r7`).
- **`$ptreg`** — 32-битный адресный указатель (`PTREG`, 4 ГБ), используемый для обращения к памяти и многократного разыменования указателей.
- **`$freg`** — 16-битный регистр флагов и состояния процессора (`FREG`, бит 11: `PRV`).
- **`$sreg`** (или **`$sp`**) — 32-битный указатель аппаратного стека (`SREG`).
- **`$ir0` .. `$ir15`** — 16 векторных 32-битных регистров адресов прерываний.
- **`$pv0` .. `$pv13`** — 14 векторных 32-битных регистров границ Зон Привилегий (7 защищенных диапазонов `[$pv0:$pv1]`..`[$pv12:$pv13]`). Только при нахождении `PC` внутри этих зон коду разрешено поднимать бит `PRV` через `MSP.or $freg, 0x0800`.
- **`$pv14` (`$rom_base`) и `$pv15` (`$rom_limit`)** — 2 векторных 32-битных регистра границ постоянной памяти ROM. При установке границ запись по этим адресам блокируется аппаратно.

### 12.2. Суффиксы размерности данных (`.b`, `.w`, `.d`)
Если инструкции требуется явно указать размер обрабатываемых данных, к мнемонике через точку добавляется суффикс:
- **`.b`** (*byte*, 8 бит / 1 байт) — например: `LMR.b $0, 0x42`, `LRM.b $1, [0x4000]`.
- **`.w`** (*word*, 16 бит / 2 байта, по умолчанию) — например: `LMR.w $0, 0x1234` (эквивалентно `LMR $0, 0x1234`).
- **`.d`** (*doubleword*, 32 бита) — например: `LMR.d $0, [0x1000]`.

### 12.3. Регистровые инструкции АЛУ и унарные операции
Арифметические инструкции формата `ADD`, `SUB`, `MUL`, `DIV`, `MOD` и однобайтовые унарные инструкции `INC`, `DEC`, `NOT` работают **только с регистрами общего назначения**:

```asm
; Трехоперандные инструкции АЛУ (Rd = Rs1 op Rs2):
ADD $0, $1, $2          ; $0 = $1 + $2
ADD R0, R1, R1          ; Классическая запись: R0 = R1 + R1
SUB $3, $0, $2          ; $3 = $0 - $2
MUL $4, $1, $2          ; $4 = $1 * $2
DIV $5, $4, $1          ; $5 = $4 / $1
MOD $6, $4, $1          ; $6 = $4 % $1

; Однобайтовые унарные инструкции (1 байт в машинном коде!):
INC $0                  ; $0 = $0 + 1 (также поддерживается INC R0)
DEC $1                  ; $1 = $1 - 1 (также поддерживается DEC R1)
NOT $2                  ; Побитовая инверсия: $2 = ~$2
```

### 12.4. Загрузка и выгрузка (`LMR` и `LRM`): числа, ссылки `[...]` и указатели
В инструкциях чтения в регистр (`LMR`) и выгрузки из регистра в память (`LRM`) синтаксис второго операнда строго разграничивает непосредственное число и ссылку на память:
- **Просто число без скобок** (`0x1234`) — непосредственное значение (для `LMR` — константа, загружаемая прямо в регистр `SRC=0`; для `LRM` — непосредственный целевой адрес `DST=0`).
- **Квадратные скобки `[...]`** — **ссылка на данные в памяти** (разыменование адреса или регистрового указателя).

Подробные примеры всех режимов адресации:

1. **Непосредственное значение (число без скобок, `SRC=0`):**
   ```asm
   LMR.w $0, 0x1234        ; Загружает само число 0x1234 в регистр $0 ($0 = 0x1234)
   LMR.b $1, 0x48          ; Загружает байт 0x48 ('H') в младший байт регистра $1
   ```
2. **Прямая ссылка на ячейку памяти (`[addr]`, `SRC=1` / `DST=1`):**
   ```asm
   LMR.w $0, [0x1000]      ; Читает 16-битное слово ИЗ памяти по адресу 0x1000 в $0 ($0 = MEM16[0x1000])
   LRM.w $0, [0x1000]      ; Выгружает 16-битное слово из $0 В память по адресу 0x1000 (MEM16[0x1000] = $0)
   LRM.b $1, [0x4000]      ; Выгружает младший байт $1 по адресу 0x4000 (например, на видеоэкран)
   ```
3. **Косвенная адресация через указатель `[$ptreg]` (`SRC=2` / `DST=2`):**
   ```asm
   LMR.w $0, [$ptreg]      ; Читает слово из памяти по 32-битному адресу, лежащему в PTREG ($0 = MEM16[PTREG])
   LRM.b $4, [$ptreg]      ; Записывает младший байт $4 в память по адресу из PTREG (MEM8[PTREG] = $4)
   ```
4. **Косвенная адресация по регистровой паре `[$0:$1]` (`SRC=3` / `DST=3`):**
   ```asm
   LMR $0, [$0:$1]         ; Формирует 32-битный поинтер из пары регистров ($0 — старший, $1 — младший)
                           ; и загружает данные по этому адресу в $0 (допускается и запись LMR, $0, [$0:$1])
   LRM $2, [$0:$1]         ; Выгружает значение $2 в память по составному указателю [$0:$1]
   ```

### 12.5. Управление спецрегистрами (`MSP`) через точечные модификаторы
Инструкция `MSP` управляет системными регистрами `$freg`, `$ptreg`, `$sreg` (`$sp`), а также 32 векторными регистрами прерываний `$ir0..$ir15` и зон `$pv0..$pv15`:

- **Наложение побитовых масок на `$freg` (`MSP.and`, `MSP.or`, `MSP.xor`, `MSP.xnor`):**
  ```asm
  MSP.and $freg, 0x0001       ; Оставить в регистре флагов только бит переноса C (FREG = FREG & 0x0001)
  MSP.or  $freg, 0x0200       ; Включить глобальное разрешение прерываний MIE
  MSP.xor $freg, $2           ; Инвертировать биты FREG маской из регистра $2 (FREG = FREG ^ $2)
  ```
- **Прямая загрузка глухой настройки или указателя (`MSP.ld`):**
  ```asm
  MSP.ld $freg, 0x0000        ; Загрузить глухую настройку 0x0000 напрямую в регистр флагов FREG
  MSP.ld $ptreg, 0x00010000   ; Загрузить непосредственный 32-битный адрес в PTREG
  MSP.ld $ptreg, [0xA000]     ; Загрузить в PTREG указатель, хранящийся в памяти по адресу 0xA000
  MSP.ld $ptreg, [$0:$1]      ; Собрать 32-битный указатель в PTREG из пары регистров: PTREG = ($0 << 16) | $1
  MSP.ld $sreg, 0x3F00        ; Загрузить начальный адрес вершины стека в SREG
  MSP.ld $sreg, [$0:$1]       ; Загрузить SREG из пары регистров: SREG = ($0 << 16) | $1

  ; Загрузка векторов прерываний и зон привилегий:
  MSP.ld $ir0, 0x00010000     ; Задать вектор аппаратного прерывания IRQ0
  MSP.ld $pv0, 0x00008000     ; Задать нижнюю границу Зоны Привилегий 0
  MSP.ld $pv1, 0x00008FFF     ; Задать верхнюю границу Зоны Привилегий 0
  ```
- **Арифметическое смещение указателей (`MSP.add`, `MSP.sub`):**
  ```asm
  MSP.add $ptreg, 0x0010      ; Сдвинуть указатель PTREG вперед на 16 байт (PTREG += 16)
  MSP.sub $ptreg, $1          ; Вычесть из PTREG значение регистра $1 (PTREG -= $1)
  MSP.add $sreg, 0x0002       ; Сдвинуть указатель стека SREG на 2 байта
  ```

### 12.6. Многократное разыменование указателей через `PTREG`
В архитектуре LIM M2 нативное аппаратное разыменование цепочек указателей (`*ptr`, `**ptr`, `***ptr`) работает именно через регистр **`PTREG`**, так как инструкция `MSP.ld $ptreg, [$ptreg]` (кодировка `SRC_MODE=10`) за один шаг считывает из памяти по текущему адресу `PTREG` новый адрес и записывает его обратно в `PTREG` (`PTREG = MEM16[PTREG]`). Для обычных регистров пришлось бы вручную выгружать и перезагружать адрес, поэтому любые многоуровневые структуры данных (связные списки, таблицы дескрипторов, деревья) удобнее всего разыменовывать в `PTREG`:

```asm
; Пусть в памяти лежит цепочка указателей:
; MEM[0xA000] -> 0xA010 -> 0xA020 -> 0xA030 (где лежит число 0xCAFE)

MSP.ld $ptreg, 0xA000       ; Начальная загрузка базового адреса в PTREG
MSP.ld $ptreg, [$ptreg]     ; 1-е разыменование: PTREG = MEM16[0xA000] = 0xA010
MSP.ld $ptreg, [$ptreg]     ; 2-е разыменование: PTREG = MEM16[0xA010] = 0xA020
MSP.ld $ptreg, [$ptreg]     ; 3-е разыменование: PTREG = MEM16[0xA020] = 0xA030

; После 3 команд в PTREG находится конечный адрес 0xA030:
LMR.w  $0, [$ptreg]         ; Читаем значение 0xCAFE в регистр $0
```

### 12.7. Переходы, стек, прерывания и директивы данных
```asm
; Метки и переходы:
start:
    JMP main_loop           ; Безусловный переход на метку (16-битный адрес)
    JMP $0                  ; Косвенный переход по адресу в регистре $0
    JMP [$ptreg]            ; 32-битный переход по адресу в PTREG
    JZ  is_zero             ; Переход, если флаг Z == 1
    JNZ not_zero            ; Переход, если флаг Z == 0
    JCR on_carry            ; Переход, если флаг переноса C == 1

; Стек и подпрограммы:
    PUSH $0                 ; Сохранить $0 на стек
    POP  $0                 ; Восстановить $0 со стека
    JSR  my_func            ; Вызов подпрограммы
    RTS                     ; Возврат из подпрограммы

; Программное прерывание (1 байт, младшие 3 бита = номер вектора 0..7):
    INTR 3                  ; Вызов вектора прерывания #3 (опкод 0xE3)
    RETI                    ; Возврат из прерывания

; Директивы размещения данных и адресации:
    .org 0x0100             ; Установить текущий адрес компиляции
    .db 0x48, 0x49, 0x00    ; Записать байты в память
    .dw 0x1234, 0xABCD      ; Записать 16-битные слова (Little-Endian)
    .dd 0x00123456          ; Записать 32-битное двойное слово
    .ascii "LIM M2"         ; Записать ASCII-строку без нуля
    .asciz "HELLO!"         ; Записать ASCII-строку с завершающим нулем
```

### 12.8. Компиляция в `.bin` и `.hex` из командной строки
Вы можете скомпилировать любой `.asm` файл одновременно в бинарный образ (`.bin`) и шестнадцатеричный дамп (`.hex`):

```bash
# Компиляция demo.asm -> demo.bin + demo.hex (создаются оба файла по умолчанию):
python3 ../compiler/compiler.py ../compiler/demo.asm -l

# Или напрямую через модуль limasm.py:
python3 ../compiler/limasm.py ../compiler/demo.asm

# Прямой запуск исходника .asm в интерактивном симуляторе (компилируется на лету):
python3 sim.py ../compiler/demo.asm -i
```
