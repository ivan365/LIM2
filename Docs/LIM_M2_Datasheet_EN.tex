\section{Document Scope and Architectural Philosophy}
This document serves as the formal architectural reference manual and hardware specification for the \textbf{LIM M2} microprocessor. The LIM M2 architecture has been deliberately designed to deliver deterministic execution, robust electrical integrity, and superior clock scaling.

A defining cornerstone of the LIM M2 datapath is the \textbf{total elimination of internal tri-state (high-impedance / Hi-Z) buses}. By substituting shared capacitive wires with actively driven multiplexer trees (Point-to-Point MUX Routing), the architecture prevents shoot-through currents, eliminates bus contention risks, and guarantees sharp, symmetrical transition edges.

\begin{limnote}{Instruction Code Allocation}
The LIM M2 instruction set architecture utilizes a contiguous 5-bit primary opcode space:
\texttt{NOP}=0, \texttt{ADD}=1, \ldots, \texttt{MSP}=26. Opcode values 27--31 are reserved for next-generation hardware extensions.
\end{limnote}

\subsection{Unified Instruction Syntax Philosophy}
The LIM M2 processor architecture strictly enforces an orthogonal operand convention: \textbf{the destination operand (target, "where to") is always declared first, followed by input source operands ("where from")}. This ensures clean, deterministic code structure across all instructions:
\begin{itemize}
  \item \textbf{Arithmetic Operations (3 Operands):} \texttt{ADD Rd, Rs1, Rs2} denotes $\text{Rd} \leftarrow \text{Rs1} + \text{Rs2}$ (e.g., \texttt{ADD R0, R1, R2} computes $R0 = R1 + R2$); similarly for \texttt{SUB}, \texttt{MUL}, \texttt{DIV}.
  \item \textbf{Logic Operations (2 Operands):} \texttt{AND Rd, Rs} denotes $\text{Rd} \leftarrow \text{Rd} \ \text{AND}\ \text{Rs}$ (e.g., \texttt{AND R0, R1} computes $R0 = R0 \ \& \ R1$); similarly for \texttt{OR}, \texttt{NAND}, \texttt{NOR}, \texttt{XOR}, \texttt{XNOR}.
  \item \textbf{Single-Byte Unary Operations (1 Operand):} \texttt{INC Rd} ($\text{Rd} \leftarrow \text{Rd} + 1$), \texttt{DEC Rd} ($\text{Rd} \leftarrow \text{Rd} - 1$), and \texttt{NOT Rd} ($\text{Rd} \leftarrow \sim\text{Rd}$). Operate on a single register \reg{Rd} in place. Encoded in exactly 1 byte (\texttt{[7:3]} opcode, \texttt{[2:0]} Rd), no second byte is fetched from memory.
  \item \textbf{Register-to-Register Transfers:} \texttt{LRR Rd, Rs} executes a direct point-to-point copy from source (point B, \reg{Rs}) to destination (point A, \reg{Rd}): $\text{Rd} \leftarrow \text{Rs}$ (e.g., \texttt{LRR R0, R1} computes $R0 = R1$).
  \item \textbf{Memory Loads (LMR):} the primary register argument \reg{Rd} designates the processor register receiving loaded data.
\end{itemize}

\section{Processor Overview}
The \textbf{LIM M2} is a versatile, high-throughput 16-bit microprogrammed processor engineered for integer-intensive computation. Architectural highlights include:

\begin{itemize}
  \item \textbf{Conflict-Free Multiplexer Datapath:} Internal signals are steered purely by push-pull multiplexer trees (\textbf{MUX 1}, \textbf{DEST-DMUX}, and \textbf{MUX 2}). This modern design is perfectly suited for high-density ASIC and modern FPGA synthesis.
  \item \textbf{Dual Accumulator Staging:} Dedicated pre-ALU accumulators (\reg{ACCA} and \reg{ACCB}) isolate the arithmetic core from the general register file, minimizing propagation path skew.
  \item \textbf{Hardware ALU Auto-Chaining (Multi-Word Arithmetic):} The ALU integrates an internal residual register (\reg{ALU\_RESIDUAL}). When an addition overflows 16 bits ($>2^{16}-1$), a subtraction produces a borrow ($<0$), or multiplication/division produces high-word residuals, the excess is retained in hardware and automatically accumulated or subtracted in the next mathematical operation. This enables continuous multi-word arithmetic (32, 48, 64+ bits) without dedicated ADC/SBB instructions. The chain is flushed using \texttt{NOP}.
  \item \textbf{Direct Reg-to-Reg Bypass:} A low-latency path from MUX 1 directly into MUX 2 enables single-cycle register transfers without locking ALU resources.
  \item \textbf{Linear 24-Bit Addressing (Up to 16 MB):} Dedicated 24-bit pointer registers (\reg{PTREG} with auto-increment and \reg{SREG} stack pointer) transcend the traditional 64 KB memory barrier, providing linear access across 16 megabytes of data and stack space.
  \item \textbf{High Clock Scaling Potential:} Unburdened by capacitive bus decay, the LIM M2 operates comfortably at a baseline frequency of \textbf{200~MHz}, scaling toward \textbf{700~MHz and above} in optimized silicon.
\end{itemize}

The lower 3 bits of the initial octet (\bits{[2:0]}) serve a dual, deterministic architectural role:
\begin{itemize}
  \item In register operations (arithmetic, unary, logic, shift, register move, stack), bits $[2:0]$ directly encode the \textbf{first register operand} (\reg{Rd} or \reg{Rs1}), enabling full 8-register addressing (\texttt{R0}--\texttt{R7}) without unnecessary decoding overhead.
  \item In instructions requiring hardware mode selection or memory/special-register selectors (\texttt{LMR}, \texttt{LRM}, \texttt{MSP}, \texttt{JMP}, \texttt{JCR}, \texttt{JNZ}, \texttt{JZ}), bits $[2:0]$ serve as the configuration/mode selector (\field{CFG} / \field{MOD} / \field{SRC} / \field{DST}).
  \item In zero-operand control instructions (\texttt{NOP}, \texttt{HALT}, \texttt{CLI}, \texttt{STI}, \texttt{RET}), these bits are set to \bits{000}.
\end{itemize}

\subsection{Class I: Single-Byte Instructions (1 Byte, 0 Extra Octets)}
Control commands (\texttt{NOP}, \texttt{HALT}, \texttt{CLI}, \texttt{STI}, \texttt{RET}) and unary register operations (\texttt{NOT}, \texttt{INC}, \texttt{DEC}) execute from a single fetched byte without requesting a second byte from memory:
\begin{itemize}
  \item Argument-less commands have \field{CFG} set to \bits{000}.
  \item Unary instructions (\texttt{INC Rd}, \texttt{DEC Rd}, \texttt{NOT Rd}) encode the target register index \reg{Rd} (\texttt{R0}--\texttt{R7}) directly in bits $[2:0]$.
\end{itemize}

\subsection{Class II: Three-Operand Arithmetic Instructions (2 Bytes)}
Arithmetic instructions (\texttt{ADD}, \texttt{SUB}, \texttt{MUL}, \texttt{DIV}, \texttt{MOD}) adhere to the universal syntax paradigm: \textbf{destination first, then operands}:
$$\texttt{ADD Rd, Rs1, Rs2} \quad \implies \quad \text{Rd} \leftarrow \text{Rs1} + \text{Rs2} + \reg{ALU\_RESIDUAL}$$
$$\texttt{MOD Rd, Rs1, Rs2} \quad \implies \quad \text{Rd} \leftarrow \text{Rs1} \pmod{\text{Rs2}}$$
The first instruction argument (destination register \reg{Rd}) is encoded directly in the lower 3 bits of Octet 0, allowing full 3-bit addressing (\texttt{R0}--\texttt{R7}) for all three operands:
\begin{itemize}
  \item \textbf{Octet 0:} Bits $[7:3]$ --- Opcode (5 bits); Bits $[2:0]$ --- Destination register \reg{Rd} (3 bits, \texttt{R0}--\texttt{R7}, 1st argument).
  \item \textbf{Octet 1:} Bits $[7:5]$ --- First source operand \reg{Rs1} (3 bits, \texttt{R0}--\texttt{R7}); Bits $[4:2]$ --- Second source operand \reg{Rs2} (3 bits, \texttt{R0}--\texttt{R7}); Bits $[1:0]$ --- Reserved (\bits{00}).
\end{itemize}

\subsection{Class IV: Register-to-Register Move (LRR, 2 Bytes)}
Instruction \texttt{LRR Rd, Rs} copies from source (point B, \reg{Rs}) to destination (point A, \reg{Rd}):
$$\texttt{LRR Rd, Rs} \quad \implies \quad \text{Rd} \leftarrow \text{Rs}$$
Data moves via the dedicated bypass path \textbf{MUX 1} $\to$ \textbf{MUX 2} bypassing the ALU in 1 cycle without affecting flags. Encoding: Octet 0 contains opcode \bits{00111} and destination register \reg{Rd} (\bits{[2:0]}). Octet 1 contains source register \reg{Rs} (\bits{[7:5]}) and reserved bits (\bits{[4:0]} = \bits{00000}).

\subsection{Class V: Hardware Comparator (CMP, 2 Bytes)}
Instruction \texttt{CMP Rs1, Rs2} non-destructively compares two register values:
\begin{itemize}
  \item \textbf{Octet 0:} Opcode \bits{01000}, bits $[2:0]$ specify the first source operand \reg{Rs1} (1st argument).
  \item \textbf{Octet 1:} Bits $[7:5]$ specify the second source operand \reg{Rs2}; bits $[4:0]$ are reserved (\bits{00000}).
\end{itemize}
The comparison updates the 2-bit field \reg{FREG.CMP} (bits $[5:4]$):
\begin{center}
\begin{tabular}{ccl}
\toprule
Value of \reg{FREG.CMP} & Condition & Meaning \\
\midrule
\texttt{01} ($01_2$) & $\text{Rs1} < \text{Rs2}$ & First operand is strictly less than second \\
\texttt{10} ($10_2$) & $\text{Rs1} = \text{Rs2}$ & Operands are equal \\
\texttt{11} ($11_2$) & $\text{Rs1} > \text{Rs2}$ & First operand is strictly greater than second \\
\texttt{00} ($00_2$) & Reset / Error & Comparator inactive or reset state \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Class VI: Iterative D-Flip-Flop Hardware Shift (BSL, BSR)}
Shift instructions \texttt{BSL Rd, shift} and \texttt{BSR Rd, shift} are physically implemented as an \textbf{iterative 16-stage D-flip-flop shift register} costing $\approx 300$ transistors instead of $\approx 30,000$ for a barrel matrix shifter:
\begin{itemize}
  \item Shifting executes cycle-by-cycle (hardware \texttt{for} loop): a 16-bit shift takes exactly 15 cycles longer than a 1-bit shift (1 cycle per bit shifted).
  \item Octet 0: Upper 5 bits hold opcode (\texttt{BSL}: \bits{11000}, \texttt{BSR}: \bits{11001}), lower 3 bits (\bits{[2:0]}) select register \reg{Rd}.
  \item Octet 1: Entire byte (\bits{[7:0]}) specifies the shift count ($0$--$16$ cycles).
  \item Injected bits are controlled by \reg{FREG}: $\reg{SMOD}=1$ rotates ejected bits into the opposite side; $\reg{SMOD}=0$ injects \reg{FREG.DBIT}.
\end{itemize}

\subsection{Class VII: Stack Operations (PUSH, POP, 2 Bytes)}
Stack instructions push/pop registers via the 24-bit stack pointer \reg{SREG}:
\begin{itemize}
  \item \textbf{Octet 0:} Opcode (\texttt{PUSH}: \bits{10110}, \texttt{POP}: \bits{10111}), bits $[2:0]$ directly designate operand register (\reg{Rs} for push, \reg{Rd} for pop, 1st argument).
  \item \textbf{Octet 1:} Bits $[7:0]$ are reserved ($00000000_2$).
\end{itemize}

\subsection{Class VIII: Special Register Manipulation (MSP, 2 Bytes)}
Instruction \texttt{MSP} manages system registers (\reg{FREG}, \reg{PTREG}, and future extensions):
\begin{itemize}
  \item \textbf{Octet 0:} Bit $[10]$ (bit 2 of octet 0) sets mode: $0$ = Direct Load, $1$ = Register Operation.
    Bits $[9:8]$ (bits 1--0 of octet 0) select register: $00_2$ = \reg{FREG}, $01_2$ = \reg{PTREG}.
  \item \textbf{Octet 1 (Dynamic by CFG):}
    \begin{itemize}
      \item \textbf{Load mode ($[10] = 0$):} For \reg{FREG}, bits $[7:5]$ select source register \reg{Rs}. For \reg{PTREG}, bits $[7:5]$ select \reg{Rs\_hi} and bits $[4:2]$ select \reg{Rs\_lo}.
      \item \textbf{Modify \reg{FREG} ($[10] = 1, [9:8] = 00$):} Bits $[7:6]$ specify bitwise operation (\bits{00}=AND, \bits{01}=OR, \bits{10}=XOR, \bits{11}=XNOR), bits $[5:3]$ select mask register \reg{Rmask}.
      \item \textbf{Modify \reg{PTREG} ($[10] = 1, [9:8] = 01$):} Bits $[7:6]$ select math operation (\bits{00}=ADD, \bits{01}=SUB), bits $[5:3]$ select single offset register \reg{Rsrc} (multi-register compound pairs prohibited). Evaluated via ALU with carry/borrow support.
    \end{itemize}
\end{itemize}

\subsection{Class IX: Branch Instructions (2--3 Bytes)}
Branches (\texttt{JMP}, \texttt{JCR}, \texttt{JNZ}, \texttt{JZ}) support 3 modes selected via \field{CFG} (bits $[2:0]$ of octet 0):
\begin{itemize}
  \item \textbf{MOD = 0 (\bits{000}): Immediate 16-bit address (3 bytes).} Followed by octets 1 and 2 encoding target address in the 64-KB code space.
  \item \textbf{MOD = 1 (\bits{001}): Indirect register branch (2 bytes).} Octet 1 bits $[7:5]$ designate source register \reg{Rs}.
  \item \textbf{MOD = 2 (\bits{010}): 24-bit pointer branch via \reg{PTREG}.} Jump to flat 24-bit physical address in \reg{PTREG}.
\end{itemize}

\subsection{Class X: Memory Transfer Instructions (LMR, LRM, 2--4 Bytes)}
Load (\texttt{LMR}) and Store (\texttt{LRM}) encode flexible operand sizing and addressing in \field{CFG}:
\begin{itemize}
  \item Bit $[2]$: Operand size \field{SZ} ($0 = 8$-bit byte, $1 = 16$-bit word).
  \item Bits $[1:0]$: Addressing mode \field{SRC} / \field{DST}:
    \begin{itemize}
      \item \textbf{0: Inline Immediate Data:} 2 bytes ($\field{SZ}=0$) or 3 bytes ($\field{SZ}=1$).
      \item \textbf{1: Immediate Pointer:} 4 bytes. Octet 1 designates register, octets 2--3 hold 16-bit address.
      \item \textbf{2: 24-Bit \reg{PTREG} Pointer:} 2 bytes. Automatically auto-increments if \texttt{FREG.AIP} is set.
      \item \textbf{3: Register Pair 24-bit Address:} 2 bytes. Octet 1 encodes $[7:5]$ (\reg{Arg1} / upper address) and $[4:2]$ (\reg{Arg2} / lower 16-bit address). In \texttt{LMR}, \reg{Arg1} receives loaded data.
    \end{itemize}
\end{itemize}

The architecture integrates external hardware service requests and internal software traps into a unified 16-vector hierarchy governed by a cycle-accurate hardware handshake.

\subsection{Hardware Handshake Protocol (RDI $\to$ IA $\to$ D0--D7)}
For robust peripheral interfacing, the processor implements a 4-phase hardware handshake cycle that completely eliminates CPU polling overhead:

\begin{enumerate}
  \item \textbf{Request Phase (RDI):} A peripheral device asserts an active-high level on the \texttt{RDI} (\textit{Raw Direct Interrupt}) pin. The core samples \texttt{RDI} at atomic micro-op boundaries.
  \item \textbf{Arbitration Phase (Mask Check):} If interrupts are enabled (\reg{FREG.MIE} = 1), the CPU commits the current datapath micro-operation and initiates the interrupt sequence.
  \item \textbf{Acknowledge Phase (IA Strobe):} The core asserts an active-high strobe on the \texttt{IA} (\textit{Interruption Accepted / Interrupt Acknowledge}, Pin~26) output. This informs all slave devices on the bus that the core is ready to ingest the interrupt vector index.
  \item \textbf{Vector Transfer Phase (D0--D7):} Concurrently with asserting \texttt{IA}, the processor switches the external bidirectional data bus \texttt{D0--D7} to input mode and activates the \texttt{RD} line. The requesting peripheral drives its 8-bit vector ID onto \texttt{D0--D7} (lower 4 bits address vectors 0--15).
  \item \textbf{Latch and Dispatch Phase:} The CPU latches the vector ID from \texttt{D0--D7}, deasserts \texttt{IA}, and advances to context preservation.
\end{enumerate}

\subsection{Context Preservation on 24-Bit Stack and Handler Entry}
Interrupt service entry is permitted strictly when the CPU is not already executing an interrupt handler (\reg{FREG.INTR} = 0) and master interrupts are unmasked (\reg{FREG.MIE} = 1). When \reg{FREG.INTR} = 1, subsequent hardware interrupt requests are locked out by hardware.

Upon interrupt acceptance, the core executes an atomic state preservation sequence:
\begin{enumerate}
  \item \textbf{Program Counter Preservation (PC):} The current instruction pointer is pushed onto the 24-bit execution stack via \reg{SREG}:
  $$\reg{SREG} \leftarrow \reg{SREG} - 2, \quad \text{Memory}[\reg{SREG}] \leftarrow \text{PC}_{15:0}$$
  \item \textbf{Status and Flags Preservation (FREG):} The complete status register (with \reg{FREG.INTR}=0) is pushed onto the stack:
  $$\reg{SREG} \leftarrow \reg{SREG} - 2, \quad \text{Memory}[\reg{SREG}] \leftarrow \reg{FREG}$$
  \item \textbf{Nested Interrupt Lockout:} The core asserts the in-interrupt flag \reg{FREG.INTR} $\leftarrow$ \texttt{1} (bit 15) and clears the mask bit \reg{FREG.MIE} $\leftarrow$ \texttt{0}, precluding nested re-entrancy and race conditions.
  \item \textbf{Vector Dispatch:} The handler address is indexed from the vector table using the ingested vector ID and loaded into \texttt{PC}.
\end{enumerate}

\subsection{Return from Interrupt}
Exiting the interrupt service routine restores the preempted execution context:
\begin{enumerate}
  \item The saved flags and processor modes are restored from the stack:
  $$\reg{FREG} \leftarrow \text{Memory}[\reg{SREG}], \quad \reg{SREG} \leftarrow \reg{SREG} + 2$$
  (Restoring \reg{FREG} automatically clears \reg{FREG.INTR} back to \texttt{0}, lifting the lockout, and restores \reg{FREG.MIE} to its previous state).
  \item The return address is popped back into the program counter:
  $$\text{PC} \leftarrow \text{Memory}[\reg{SREG}], \quad \reg{SREG} \leftarrow \reg{SREG} + 2$$
  \item Normal instruction execution seamlessly resumes on the subsequent clock cycle with zero data corruption.
\end{enumerate}

\section{Conclusion}
The \textbf{LIM M2} architecture harmonizes the time-tested reliability of deterministic microprogramming with the modern performance of an entirely tri-state-free multiplexer datapath. By eliminating bus contention, floating nodes, and capacitive decay, the LIM M2 guarantees exceptional signal fidelity and opens an unprecedented clock frequency envelope spanning from 200~MHz to the highest thresholds of modern silicon.
