## 🚀 Использование из командной строки

### 1. Быстрая компиляция в `.bin` и `.hex`
Компилятор автоматически генерирует одновременно чистый бинарный файл (`.bin`) и шестнадцатеричный файл (`.hex`):

```bash
# Использование через compiler.py:
python3 LIM2/compiler/compiler.py LIM2/compiler/demo.asm

# Или напрямую через limasm.py:
python3 LIM2/compiler/limasm.py LIM2/compiler/demo.asm
```

Ключ `-l` (или `--list`) выводит таблицу всех меток и побайтовый дизассемблированный листинг инструкций:

```bash
python3 LIM2/compiler/compiler.py LIM2/compiler/demo.asm -l
```

## 📖 Спецификация языка ассемблера

### 1. Регистры и поддерживаемые алиасы

Компилятор поддерживает гибкую систему алиасов (псевдонимов) для всех регистров. Префикс `$` является стандартным, но компилятор также принимает имена без префикса (`r0`, `freg`, `sp`):

| Регистр / Вектор | Разрядность | Основные имена и алиасы | Назначение в архитектуре |
| :--- | :---: | :--- | :--- |
| **РOН (0..7)** | 16 бит | `$0`..`$7`, `R0`..`R7`, `$r0`..`$r7`, `0`..`7` | Регистры общего назначения для вычислений и адресации |
| **`PTREG`** | 32 бита | `$ptreg`, `ptreg` | Указатель линейного адресного пространства (4 ГБ) с аппаратным автоинкрементом `AIP` |
| **`FREG`** | 16 бит | `$freg`, `freg` | Регистр флагов и статуса процессора (`ZF`, `CF`, `OF`, `EM`, `CMP`, `CLK`, `SSRC`, `MIE`, `DWR`, `PRV`, `AIP`, `DBIT`, `SMOD`, `INTR`) |
| **`SP` / `SREG`** | 32 бита | `$sp`, `sp`, `$sreg`, `sreg` | 32-битный указатель аппаратного системного стека |
| **Таймер 1 (счетчик)** | 32 бита | `t1_cnt`, `$t1_cnt` (`t1_cnt_lo`, `t1_cnt_hi`) | 32-битный инкрементный счетчик тактов Timer 1 (ячейки 64, 65) |
| **Таймер 1 (компаратор)** | 32 бита | `t1_match`, `$t1_match` (`t1_match_lo`, `hi`) | 32-битный регистр совпадения/частоты (ячейки 66, 67, вызывает IRQ 12) |
| **Таймер 1 (время)** | 32 бита | `t1_time`, `$t1_time` (`t1_time_lo`, `hi`) | 32-битный накопитель реального времени в секундах/мс (ячейки 68, 69) |
| **Таймер 2 (периодический)**| 32 бита | `t2_cnt`, `$t2_cnt` (`t2_cnt_lo`, `hi`) | 32-битный декрементный счетчик тактов Timer 2 (ячейки 70, 71) |
| **Таймер 2 (перезагрузка)** | 32 бита | `t2_reload`, `$t2_reload` (`t2_reload_lo`, `hi`) | 32-битный период перезагрузки Timer 2 (ячейки 72, 73, вызывает IRQ 13) |
| **Таймер 3 (разовый)** | 32 бита | `t3_cnt`, `$t3_cnt` (`t3_cnt_lo`, `hi`) | 32-битный разовый обратный отсчет (ячейки 74, 75, вызывает IRQ 14) |
| **Таймер 4 (квант задач)** | 16 бит | `t4_cnt`, `$t4_cnt` | 16-битный счетчик завершенных инструкций ядра (ячейка 76) |
| **Таймер 4 (квант перезагр.)**| 16 бит | `t4_reload`, `$t4_reload` | 16-битное число инструкций до вызова IRQ 15 вытеснения ОС (ячейка 77) |
| **`TSR` (настройка таймеров)**| 16 бит | `tsr`, `$tsr`, `timer_ctrl` | Регистр управления 4 аппаратными таймерами (ячейка 78, EN, IE, IF) |
| **Сквозные векторы** | 32 бита | **`$vec0` .. `$vec31`**, `vec0`..`vec31` | Прямой доступ к любому из 32 системных векторов по сквозному номеру `0..31` |
| **Векторы прерываний** | 32 бита | **`$ir0` .. `$ir15`**, `ir0`..`ir15` | 16 векторов аппаратных прерываний IVT (`$vec0`..`$vec15`) |
| **Зоны привилегий** | 32 бита | **`$pv0` .. `$pv13`**, `pv0`..`pv13` | Границы 7 защищенных Зон Привилегий (`$vec16`..`$vec29`) |
| **Граница RAM / ROM (низ)** | 32 бита | **`$pv14`**, **`$ram_base`**, **`$ram_start`**, **`$rom_base`**, **`$rom_start`** | Нижняя граница адресного диапазона памяти (`$vec30`) |
| **Граница RAM / ROM (верх)** | 32 бита | **`$pv15`**, **`$ram_limit`**, **`$ram_end`**, **`$rom_limit`**, **`$rom_end`** | Верхняя граница адресного диапазона памяти (`$vec31`) |

### 2. Суффиксы размера операндов
Инструкции обмена с памятью `LMR` и `LRM` поддерживают строго два размера (аппаратный бит `SZ`):
* `.b` (*byte*, 8 бит / 1 байт, `SZ=0`) — например: `LMR.b $0, 0x42`, `LRM.b $0, [0x1000]`
* `.w` (*word*, 16 бит / 2 байта, `SZ=1`, по умолчанию) — например: `LMR.w $0, 0x1234` или `LMR $0, 0x1234`
*(Для 24/32-битных данных используются директивы `dp`/`dd` и команда `MSP.ld`).*

### 3. Регистровая арифметика и унарные инструкции
```asm
ADD $0, $1, $2          ; $0 = $1 + $2 (также: ADD R0, R1, R1)
SUB $3, $0, $2          ; $3 = $0 - $2
MUL $4, $1, $2          ; $4 = $1 * $2
DIV $5, $4, $1          ; $5 = $4 / $1
MOD $6, $4, $1          ; $6 = $4 % $1
INC $0                  ; $0 = $0 + 1 (1-байтовая инструкция)
DEC $1                  ; $1 = $1 - 1 (1-байтовая инструкция)
BSL $0                  ; Логический сдвиг $0 влево на 1 бит (1-байтовая инструкция)
BSR $0                  ; Логический сдвиг $0 вправо на 1 бит (1-байтовая инструкция)
NOT $2                  ; $2 = ~$2    (2-байтовая инструкция)
NOT $2, $1              ; $2 = ~$1    (2-байтовая инструкция с источником)
```

### 4. Режимы адресации памяти (`LMR` и `LRM`)
* **Число без скобок** — непосредственное значение (`SRC=0` / `DST=0`):
  ```asm
  LMR.w $0, 0x1234      ; $0 = 0x1234 (3 байта для .w, 2 байта для .b)
  ```
* **Квадратные скобки `[addr]`** — прямая ссылка на память через 32-битный указатель (`SRC=1` / `DST=1`, 5 байт):
  ```asm
  LMR.w $0, [0x00001000] ; Чтение MEM16[0x1000] в $0 (1 байт префикс + 4 байта адреса Little-Endian)
  LRM.w $0, [0x00001000] ; Запись $0 в MEM16[0x1000]
  ```
* **Указатель в `PTREG` (`[$ptreg]`, `SRC=2` / `DST=2`, 1 байт):**
  Аппаратный автоинкремент `PTREG` включен по умолчанию (`FREG.AIP = 1`). При каждом обращении указатель автоматически продвигается на размер операции:
  * `LMR.b` / `LRM.b` — инкремент на **+1 байт**;
  * `LMR.w` / `LRM.w` — инкремент на **+2 байта** (слово).
  ```asm
  LMR.w $0, [$ptreg]    ; Чтение слова по 32-битному адресу PTREG (с автоинкрементом PTREG += 2)
  LRM.b $4, [$ptreg]    ; Запись байта $4 по адресу PTREG (с автоинкрементом PTREG += 1)
  ```
* **Составной 32-битный поинтер из пары регистров `[$0:$1]` (`SRC=3` / `DST=3`, 2 байта):**
  ```asm
  LMR $0, [$0:$1]       ; Чтение по 32-битному адресу ($0 << 16) | $1
  LRM $2, [$0:$1]       ; Запись по 32-битному адресу ($0 << 16) | $1
  ```

### 5. Квантованные системные регистры (`MSP`), векторы и управление состоянием
Инструкция `MSP` (Opcode 26 / `0b11010`) использует строго квантованный 16-битный подход.
Все системные регистры процессора разбиты на 16-битные ячейки с номерами `REG_ID` от 0 до 255.
Байт 0 содержит опкод (биты 7:3) и код операции (биты 2:0):
* `000` (`ld`): прямая загрузка 16-битного immediate (`SYS_REG[id] = imm16`, 4 байта)
* `001` (`ldr` / `ldr7`): быстрая загрузка системного регистра из R7 (`SYS_REG[id] = R7`, 2 байта)
* `010` (`str` / `str7`): быстрая выгрузка системного регистра в R7 (`R7 = SYS_REG[id]`, 2 байта)
* `011` (`and`): побитовое И (`SYS_REG[id] &= imm16`, 4 байта)
* `100` (`or`): побитовое ИЛИ (`SYS_REG[id] |= imm16`, 4 байта)
* `101` (`xor`): побитовое исключающее ИЛИ (`SYS_REG[id] ^= imm16`, 4 байта)
* `110` (`onb`): побитовое включение битов по маске (`SYS_REG[id] |= imm16`, 4 байта)
* `111` (`offb`): побитовое выключение битов по маске (`SYS_REG[id] &= ~imm16`, 4 байта)

```asm
; 1. Регистр флагов FREG (ячейка 128):
MSP.ld   freg, 0x1800    ; Прямая установка флагов (FREG = 0x1800, PRV=1, AIP=1)
MSP.and  freg, 0x0001    ; Оставить только бит 0 (ZF)
MSP.or   freg, 0x0200    ; Включить прерывания (MIE, бит 9)
MSP.onb  freg, 0x0200    ; Атомарно включить бит 9
MSP.offb freg, 0x0200    ; Атомарно выключить бит 9

; 2. Быстрый обмен с регистром общего назначения R7 (по 2 байта, префиксы ldr и str):
MSP.str  freg            ; R7 = FREG (сохранение состояния)
PUSH     $7              ; Сохранить флаги в стек
MSP.ldr  freg            ; Восстановить FREG из R7

; 3. Настройка 4 аппаратных таймеров (ячейки 64..78):
MSP.ld   t1_match, 50000 ; 1 мс тик на 50 МГц (IRQ 12)
MSP.ld   t1_time, 0      ; Сброс счетчика времени
MSP.ld   t4_reload, 1000 ; Квант ОС в 1000 инструкций (IRQ 15)
MSP.ld   t4_cnt, 1000
MSP.onb  tsr, 0x9900     ; Включить T1_EN, T4_EN и их прерывания T1_IE, T4_IE

; 4. Прямая работа с 16-битными ячейками по их номерам или именам:
MSP.ld   0, 0xA000       ; ir0_lo (младшие 16 бит вектора IRQ0)
MSP.ld   1, 0x0001       ; ir0_hi (старшие 16 бит вектора IRQ0)

; 5. Настройка составных 32-битных регистров (авторасширение в 2 инструкции по 4 байта):
MSP.ld   sp, 0x00003F00    ; Установка вершины стека SREG (sp_lo=129, sp_hi=130)
MSP.ld   ptreg, 0x00010000 ; Указатель PTREG (ptreg_lo=131, ptreg_hi=132)
MSP.ld   ir0, 0x00010000   ; Вектор прерывания IRQ0 (ir0_lo=0, ir0_hi=1)
MSP.ld   $pv0, 0x00008000   ; Нижняя граница Зоны 0 ($pv0_lo=32, $pv0_hi=33)
MSP.ld   $pv1, 0x00008FFF   ; Верхняя граница Зоны 0 ($pv1_lo=34, $pv1_hi=35)
MSP.ld   $ram_base, 0x00000000  ; База RAM ($ram_base_lo=60, $ram_base_hi=61)
MSP.ld   $ram_limit, 0x00003FFF ; Лимит RAM ($ram_limit_lo=62, $ram_limit_hi=63)
```

#### Карта квантованных 16-битных ячеек (REG_ID 0..255)
| Диапазон REG_ID | Имя / Назначение | Описание |
| :---: | :--- | :--- |
| **0 – 31** | `INT_VEC` (16 пар: `$ir0_lo`..`$ir15_hi`) | 16 векторов прерываний (чётный ID — `_lo`, нечётный ID — `_hi`) |
| **32 – 59** | `PVZ_VEC` (14 пар: `$pv0_lo`..`$pv13_hi`) | 7 зон защиты привилегий (Start/End пары) |
| **60, 61** | `MEM_VEC_BASE` (`$ram_base_lo`, `_hi`) | Физический базовый адрес оперативной памяти (RAM) |
| **62, 63** | `MEM_VEC_LIMIT` (`$ram_limit_lo`, `_hi`)| Верхний лимит адресов оперативной памяти (RAM) |
| **64 – 78** | `SYS_REG_EXT[0..14]` (15 ячеек) | Зарезервированные 16-битные системные регистры для расширений |
| **79 – 127** | `RESERVED` | Зарезервировано |
| **128** | `FREG` | 16-битный регистр флагов и статуса процессора |
| **129, 130** | `SP_LO`, `SP_HI` (`$sp_lo`, `$sp_hi`) | 32-битный указатель вершины аппаратного стека SREG |
| **131, 132** | `PTREG_LO`, `PTREG_HI` (`$ptreg_lo`, `_hi`) | 32-битный указатель потоковой передачи и таблиц PTREG |
| **133 – 255** | `RESERVED` | Зарезервировано |

### 6. Переходы и вызовы подпрограмм (`JMP`, `JCR`, `JZ`, `JNZ`, `JO`, `JNO`, `CALL`)
Все инструкции переходов и вызовов строго соответствуют 32-битной адресной шине и поддерживают 4 унифицированных режима адресации:
* **Прямой переход по непосредственному адресу/метке (`MOD=0`, 5 байт):**
  ```asm
  JMP loop_start        ; Безусловный 32-битный переход на адрес метки
  CALL my_subroutine    ; Вызов подпрограммы (сохранение 32-битного PC и FREG в стек)
  JZ  is_zero           ; Переход, если флаг ZF == 1
  JNZ not_zero          ; Переход, если флаг ZF == 0
  JO  is_overflow       ; Переход, если флаг переполнения OF == 1
  JNO not_overflow      ; Переход, если флаг OF == 0
  ```
* **Косвенный переход по адресу в памяти (`MOD=1`, 5 байт):**
  ```asm
  JMP [func_ptr]        ; Переход по 32-битному адресу, прочитанному из ячейки памяти func_ptr
  CALL [vtable_slot]    ; Косвенный вызов через 32-битную ячейку в памяти
  ```
* **Косвенный переход по указателю PTREG (`MOD=2`, 1 байт):**
  ```asm
  JMP [$ptreg]          ; 1-байтовый супербыстрый переход по адресу из PTREG
  ```
* **Косвенный переход по регистровой паре (`MOD=3`, 2 байта):**
  ```asm
  JMP [$0:$1]           ; Переход по 32-битному адресу ($0 << 16) | $1
  CALL [$0:$1]          ; Вызов по 32-битному составному адресу
  ```

* **Условный переход по результату сравнения `JCR` (Jump Compare Result, Opcode 10):**
  Проверяет результат аппаратного сравнения в битах `5:4` флагового регистра `FREG` (`01`: `<`, `10`: `==`, `11`: `>`).
  Поле конфигурации `CFG [2:0]` в 1-м байте инструкции:
  - Бит 2: `INV` (`0` = условие совпадает, `1` = инверсия/не совпадает)
  - Биты `1–0`: ожидаемый код сравнения (`01` = `<`, `10` = `==`, `11` = `>`)
  - Комбинации условий: `<` (`001`), `==` (`010`), `>` (`011`), `>=` (`101`), `!=` (`110`), `<=` (`111`).
  - Целевой адрес перехода `target32` занимает полные **4 байта Little-Endian** (32 бита).

  Поддерживается **два варианта синтаксиса**:
  1. **Упрощенный составной макрос (7 байт):**
     ```asm
     JCR $1 > $2, loop_target   ; Автоматически разворачивается в:
                                ; 1) CMP $1, $2 (2 байта)
                                ; 2) JCR >, loop_target (5 байт)
     JCR $3 <= $4, exit_label
     ```
  2. **Ручной синтаксис (5 байт):**
     ```asm
     CMP $0, $1
     JCR <, on_less             ; Переход, если $0 < $1 (5 байт)
     JCR ==, on_equal           ; Переход, если $0 == $1 (5 байт)
     JCR >, on_greater          ; Переход, если $0 > $1 (5 байт)
     JCR >=, on_ge              ; Переход, если $0 >= $1 (5 байт)
     JCR !=, on_ne              ; Переход, если $0 != $1 (5 байт)
     JCR <=, on_le              ; Переход, если $0 <= $1 (5 байт)
     ; Также поддерживается точечная форма:
     JCR.GT on_greater
     JCR.EQ on_equal
     ```

### 7. Символы адресации и счетчика команд
* `$` — Текущий адрес команды / текущий location counter (Program Counter). Не конфликтует с регистрами `$0`..`$7`.
  ```asm
  msg: db "HELLO"
  msg_len = $ - msg     ; Вычисление длины буфера
  ```
* `$$` — Базовый адрес текущей программы или текущей секции `.org`.
* `.` — Синоним `$`.
* `__LINE__` — Текущий номер строки в исходнике.

### 8. Директивы данных (Порядок байт: Little-Endian)
Все операнды инструкций (непосредственные значения `imm16`/`imm32`, адреса переходов и указатели памяти) и данные размещаются в памяти в строгом формате **Little-Endian** (младшие байты первыми, по младшим адресам):

* **`db`** (`.byte`) — 1 голый байт (или строка): `db 0x42`, `db "LIM2", 0`
* **`dw`** (`.word`) — 2 голых байта (16 бит, Little-Endian): `dw 0x1234` $\to$ `[0x34, 0x12]`
* **`dp`** (`.ptr`, `dt`) — **3-байтный указатель** (24 бита, Little-Endian) для экономии памяти адресации: `dp 0x018000` $\to$ `[0x00, 0x80, 0x01]` (вместо 4 байт тратит ровно 3 байта!)
* **`dd`** (`.dword`) — 4 голых байта (32 бита, Little-Endian): `dd 0x12345678` $\to$ `[0x78, 0x56, 0x34, 0x12]`
