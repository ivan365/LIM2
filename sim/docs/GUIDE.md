# Полное руководство по архитектуре и симулятору LIM2

Исчерпывающее техническое руководство по низкоуровневой платформе симулятора процессора, шины и периферийных устройств **LIM2** (Pure Python).

---

## 1. Философия и архитектурная модель

Симулятор **LIM2** спроектирован так, чтобы дать разработчику абсолютный контроль над каждым транзистором, регистром, шиной и ножкой без использования тяжелых внешних библиотек и скрытой магии:
1. **100% Чистый Python (Zero Dependencies):** Никаких внешних библиотек (C-биндингов, сторонних движков). Весь код можно открыть, понять и модифицировать.
2. **Конфигурация платформы прямо в коде (`sim.py`):** Вся материнская плата, распределение адресов (Memory Map), мониторы и контроллеры объявляются в коде на Python. Больше **не нужно вводить длинные флаги командной строки** (`-m`, `-v`) при каждом запуске!
3. **Честная симуляция сигнальных линий (Pins):** Линии управления (`RD`, `WR`, `MREQ`, `IORQ`, `CS`, `IRQ`, `RF`) и любые произвольные ножки симулируются с поддержкой стробов и коллбэков.
4. **Аппаратное отставание памяти (Latency & Wait States):** Возможность задавать задержку выборки ячеек памяти в тактах шины и отрабатывать протокол готовности данных через ножку `RF` (Ready Flag).
5. **Превосходный TUI-интерфейс:** Многоколоночная адаптивная визуализация процессора в виде микросхем, окон памяти устройств, текстовых видеомониторов и карты адресного пространства в стиле *diskmgmt.msc*.

---

### Поддерживаемые форматы файлов программ:
Симулятор автоматически распознает формат по расширению:
- `.bin` — сырой бинарный исполняемый код процессора (Firmware / Kernel binary image).
- `.hex` — текстовые шестнадцатеричные файлы или формат Intel HEX (`:100000...`).
- `.asm` / `.lasm` — ассемблерные листинги с автоматической трансляцией в машинный код.

### Запуск интерактивного отладчика:
```bash
cd LIM2/sim
# Запуск с .hex или .bin файлом:
python3 sim.py demo.hex -i
python3 sim.py kernel.bin -i
```
Симулятор автоматически запустится со всеми устройствами, настроенными в коде `sim.py`.

### Режим долговременной работы (Long-Term Work, `-L`):
Флаг `-L` (или `--long-term [DUMP_FILE]`) переводит симулятор в режим непрерывной сессии:
```bash
# Использование дампа по умолчанию (lim2_state.dump):
python3 sim.py demo.bin -i -L

# Или с указанием собственного файла снимка:
python3 sim.py demo.bin -i -L my_system.dump
```
- **При старте:** если файл дампа существует, симулятор бесшовно восстанавливает полное состояние машины: счетчик команд `PC`, регистры, флаги, ОЗУ и видеопамять.
- **При выходе (Ctrl+C или 'q'):** симулятор автоматически сохраняет снимок всей машины обратно в дамп!

### Пакетный запуск (Batch Mode):
```bash
python3 sim.py demo.bin -n 1000
```

## 3. Анатомия процессора: Построчный разбор (`lim2_cpu.py`)

Процессор наследуется от базового класса `BaseCPU` ([`core.py`](../core.py)) и состоит из 3 ключевых методов:
- `setup(self)` — объявление регистрового файла, разрядности, ролей и флагов.
- `on_start(self)` — начальное состояние при включении питания или аппаратном сбросе (`reset`).
- `on_step(self)` — выборка байтов, склейка машинного слова, парсинг битов и исполнение инструкций.

---

### 3.1. Создание регистров (`setup`)

Каждый регистр объявляется вызовом метода `self.reg(...)`. Разберем подробно назначение каждого аргумента:

```python
def setup(self):
    # Регистры общего назначения (16 бит каждый)
    for i in range(8):
        self.reg(
            name=f"r{i}",      # 1. Системное имя регистра (доступно как self.r0, self.r1)
            bits=16,           # 2. Разрядность в битах (маска 0xFFFF рассчитывается автоматически)
            default=0,         # 3. Значение при старте и сбросе
            indexed=True,      # 4. Флаг индексируемости: разрешает доступ по номеру self.get_reg(i)
            title=f"R{i}",     # 5. Красивая подпись на микросхеме в графическом интерфейсе
            role="General",    # 6. Роль регистра для документации
            block="core"       # 7. Функциональный блок процессора
        )
```

#### Что делает каждый параметр:
1. `name`: Строковое имя регистра. Создает динамический доступ: `cpu.r0 = 0x42` или `val = cpu.r0`.
2. `bits`: Битность регистра. Внутри вычисляется маска `mask = (1 << bits) - 1`. Если записать в 16-битный регистр число `0x10005`, значение автоматически ужмется по маске до `0x0005`. Переполнение разрядной сетки контролируется аппаратной маской!
3. `default`: Начальное значение при подаче питания и вызове аппаратного сброса `cpu.reset()`.
4. `indexed=True`: Решающий флаг! Позволяет обращаться к регистру по целочисленному индексу: `self.get_reg(0)` и `self.set_reg(0, val)`. Когда номер регистра декодируется из битов инструкции (например `rd = 3`), вы просто вызываете `self.set_reg(rd, result)`.
5. `title`: Текстовое имя, отображаемое на микросхеме в ASCII-дашборде.
6. `is_acc=True`: Помечает регистр как аккумулятор ALU (`acca`, `accb`).
7. `is_pc=True`: Помечает регистр как программный счетчик (Program Counter).

---

#### 3.2. Как устроен Program Counter (Счетчик команд, PC)

Счетчик команд объявляется с флагом `is_pc=True`:
```python
self.reg("pc", bits=16, default=0x0000, is_pc=True, title="PC")
```

#### Ручная работа с Program Counter (`self.pc += 1`):
В симуляторе LIM2 вы имеете **абсолютный ручной контроль над программным счетчиком**:
* **Чтение текущего адреса:** `self.pc`
* **Прямой ручной инкремент счетчика:**
  ```python
  self.pc += 1    # переходим к следующему байту
  self.pc += 2    # пропускаем слово
  ```
  > [!TIP]
  > При выполнении `self.pc += 1` переполнение разрядной сетки (например `0xFFFF + 1 -> 0x0000`) отсекается аппаратной маской регистра автоматически!
* **Чтение байта из шины по PC:**
  ```python
  byte = self.bus.read8(self.pc)
  self.pc += 1
  ```
* **Прямые и относительные переходы (Jumps):**
  - Безусловный переход: `self.pc = target_addr`
  - Относительный переход: `self.pc += offset` (например `self.pc += -4`)
  - Условный переход:
    ```python
    if self.get_flag("ZF") == 1:
        self.pc = target_addr
    ```

---

### 3.3. Создание и управление флагами (`FREG`)

Регистр флагов объявляется с параметром `is_flag=True` и списком описания битов `flag_layout`:

```python
flag_layout = [
    # (Имя флага, Полное описание, Номер бита в регистре)
    ("ZF", "Zero", 0),          # Бит 0: Флаг нуля (результат операции равен 0)
    ("CF", "Carry", 1),         # Бит 1: Флаг переноса из старшего бита
    ("OF", "Overflow", 2),      # Бит 2: Флаг знакового переполнения
    ("EM", "ErrMath", 3),       # Бит 3: Математическая ошибка (деление на ноль)
    ("PIE", "ProgInt", 8),      # Бит 8: Разрешение программных прерываний
    ("MIE", "MasterInt", 9),    # Бит 9: Глобальное разрешение прерываний
    ("M24", "24-bit Mode", 11), # Бит 11: Режим 24-битной адресации
]
self.reg("freg", bits=16, default=0, is_flag=True, flag_layout=flag_layout, title="FREG")
```

#### Как проверять и изменять флаги:
1. **По именам флагов (рекомендуемый способ):**
   ```python
   # Установить флаг нуля:
   self.set_flag("ZF", 1)

   # Сбросить флаг переноса:
   self.set_flag("CF", 0)

   # Проверить флаг в условии перехода:
   if self.get_flag("ZF") == 1:
       self.pc = target_addr
   ```
2. **Через битовые маски напрямую:**
   ```python
   # ZF находится в бите 0:
   is_zero = (result & 0xFFFF) == 0
   self.freg = (self.freg & ~0x01) | (1 if is_zero else 0)
   ```
В графическом интерфейсе каждый бит регистра флагов отображается отдельным интерактивным индикатором `[ZF:1]`, `[CF:0]`.

### 3.4. Выборка, ручной инкремент PC и битовый парсер (`on_step`)

В методе `on_step()` все низкоуровневые действия вы пишете вручную:

```python
def on_step(self):
    # 1. Пошаговая выборка двух 8-битных байтов (char) с РУЧНЫМ инкрементом PC:
    b0 = self.bus.read8(self.pc)
    self.pc += 1

    b1 = self.bus.read8(self.pc)
    self.pc += 1

    # 2. Вручную склеиваем два байта на шине данных (databus) в 16-битную инструкцию:
    self.databus = (b0 << 8) | b1

    # 3. Декодируем поля с помощью конструктора парсинга бит:
    opcode, cfg, rd, rs1, rs2 = self.parse("[15-11] [10-8] [7-5] [4-2] [1-0]")
```
```

#### Как работает шаблон `parse(...)`:
* `[15-11]` — извлекает диапазон битов 15..11 (5 бит, число от 0 до 31).
* `[15]` — **парсинг ровно 1 бита**: извлекает бит 15 (значение 0 или 1).
* `[sign:15] [exp:14-10]` — поддержка необязательных меток полей для наглядности.

#### Примеры гибкого использования `self.parse`:
1. **Парсинг одного поля в переменную (число int):**
   ```python
   opcode = self.parse("[15-11]")
   if opcode == 1:
       print("Это команда ADD")
   ```
   > [!NOTE]
   > При парсинге одиночного диапазона результат ведет себя как обычное число `int`: его можно сравнивать (`opcode == 1`, `opcode < 10`), складывать (`opcode + 1`), форматировать (`f"0x{opcode:02X}"`) и использовать как индекс. При этом сохраняется и возможность распаковки через кортеж: `opcode, = self.parse("[15-11]")`.

2. **Парсинг одиночного бита (0 или 1):**
   ```python
   is_immediate = self.parse("[15]")  # 15-й бит (0 или 1)
   if is_immediate:
       # обработка флага
       pass
   ```

3. **Смешанный парсинг (одиночные биты + диапазоны):**
   ```python
   # 1 бит флага + 3 бита режима + 4 бита регистра:
   has_imm, mode, reg = self.parse("[15] [14-12] [11-8]")
   ```

4. **Парсинг из произвольной переменной (не только databus):**
   ```python
   high_nibble, low_nibble = self.parse("[7-4] [3-0]", value=my_byte)
   ```

#### Логика опкодов на чистом Python:
```python
    if opcode == 0:
        pass  # NOP — нет операции

    elif opcode == 1:
        # ADD Rd, Rs1, Rs2 (Сложение двух регистров)
        val1 = self.get_reg(rs1)
        val2 = self.get_reg(rs2)
        res = val1 + val2
        self.set_reg(rd, res)
        self.set_flag("ZF", 1 if (res & 0xFFFF) == 0 else 0)

    elif opcode == 5:
        # LOAD Rd, [Rs1] (Чтение 16-битного слова из памяти)
        addr = self.get_reg(rs1)
        val = self.bus.read16(addr)
        self.set_reg(rd, val)

    elif opcode == 6:
        # STORE [Rd], Rs1 (Запись 16-битного слова в память)
        addr = self.get_reg(rd)
        val = self.get_reg(rs1)
        self.bus.write16(addr, val)

    elif opcode == 31:
        # HALT — останов процессора
        self.halt()
```

## 4. Конфигурация платформы и устройств в коде (`sim.py`)

Все устройства материнской платы объявляются в функции `setup_platform(bus)` внутри файла [`sim.py`](../sim.py). Больше никаких аргументов командной строки передавать не требуется!

```python
def setup_platform(bus: MemoryBus):
    # 1. Системное ОЗУ (0x0000 .. 0x3FFF = 16 КБ)
    bus.attach(RAMDevice(start=0x0000, end=0x3FFF, name="RAM"))

    # 2. Текстовый видеомонитор 20x4 с предустановленным текстом (default_data):
    bus.attach(TextScreenDevice(
        start=0x8000,
        width=20,
        height=4,
        name="MONITOR",
        default_data="LIM2 SYSTEM READY..."  # Текст сразу появится на экране!
    ))

    # 3. ПЗУ (ROM) с байтами BIOS или шестнадцатеричным дампом:
    bus.attach(ROMDevice(
        start=0xF800,
        end=0xFFFF,
        name="BIOS",
        default_data="08 66 F8 00 12 34 00 00"  # Шестнадцатеричная строка
    ))

    # 4. Последовательный порт UART (0xF000 .. 0xF003)
    bus.attach(UARTDevice(start=0xF000, name="UART0"))

    # 5. Аппаратный таймер (0xF010 .. 0xF013)
    bus.attach(TimerDevice(start=0xF010, name="TIMER0", irq_pin="IRQ"))
```

### Предварительная инициализация устройств (`default_data` и `default_offset`)
При создании любого устройства (`RAMDevice`, `ROMDevice`, `TextScreenDevice`, `create_dev`) можно сразу заполнить его начальными данными. Поддерживаются любые типы данных:
- **ASCII строка:** `default_data="HELLO CPU!"` — кодируется в байты символов.
- **Шестнадцатеричная строка:** `default_data="AA BB CC 01 02 03"` или `"0xAA 0xBB 0xCC"`.
- **Список чисел / байты:** `default_data=[0x12, 0x34]` или `default_data=bytes([0x55, 0xAA])`.
- **Путь к файлу прошивки:** `default_data="boot.bin"` — файл автоматически прочитается с диска.
- **Смещение `default_offset`:** адрес внутри устройства, с которого начинается запись данных (по умолчанию `0`).

Каждое устройство занимает непрерывный диапазон адресов `[start .. end]` и сразу же отображается на карте памяти:
```text
┌── [КАРТА АДРЕСНОГО ПРОСТРАНСТВА ШИНЫ (0x0000..0xFFFF, 16 бит)] ──────────────┐
│ РАСПРЕДЕЛЕНИЕ ПАМЯТИ УСТРОЙСТВ (DISKMGMT.MSC STYLE):                         │
│ ┌───────────────┬────────────────┬────┬────────────────┬────┬────┬────┬────┐ │
│ │      RAM      │   [Свободно]   │MONI│   [Свободно]   │UART│ ░░ │TIME│ ░░ │ │
│ ├───────────────┼────────────────┼────┼────────────────┼────┼────┼────┼────┤ │
│ │0x0000..0x3FFF │ 0x4000..0x7FFF │8000│ 0x8050..0xEFFF │F000│F004│F010│F014│ │
│ │  16 КБ (25%)  │     25.0%      │ 0% │     43.6%      │ 0% │0.0%│ 0% │6.2%│ │
│ └───────────────┴────────────────┴────┴────────────────┴────┴────┴────┴────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 5. Как связать устройства друг с другом и с процессором

Взаимодействие компонентов в симуляторе LIM2 строится по двум аппаратным принципам:
1. **Memory-Mapped I/O (MMIO):** Обращение через шину адреса и данных.
2. **Сигнальные ножки (Pins & Signals):** Аппаратные стробы и прерывания.

### Способ 1: Общение процессора с устройством через MMIO
Когда процессор выполняет команду записи:
```python
self.bus.write8(0x8000, ord('A'))
```
1. Шина `MemoryBus` проверяет адрес `0x8000`.
2. Находит устройство `MONITOR` (диапазон `0x8000..0x804F`).
3. Вызывает метод `device.write(offset=0, value=65)`.
4. Символ `'A'` немедленно отображается в видеопамяти и на экране монитора.

### Способ 2: Прерывания от таймера к процессору через ножку IRQ
1. В таймере `TIMER0` на каждом такте уменьшается счетчик.
2. Когда счетчик равен 0, таймер поднимает сигнал на ножке шины:
   ```python
   self.bus.pins.IRQ.set(1)
   ```
3. Процессор в начале метода `on_step()` может проверить:
   ```python
   if self.bus.pins.IRQ.get() == 1 and self.get_flag("MIE"):
       # Обработка прерывания: сохраняем PC в стек и переходим по вектору
       self.handle_interrupt(vector=0x0020)
       self.bus.pins.IRQ.set(0)  # Сбрасываем флаг прерывания
   ```

### Способ 3: Прямая связь устройств через слушатели ножек (`listen`)
Одно устройство может напрямую подписаться на изменение сигнала другого:
```python
# Устройство Б слушает сигнал ACK от устройства А:
bus.pins.DEV_A_ACK.listen(lambda val: print(f"Устройство Б получило сигнал: {val}"))
```

## 6. Поддержка ножек, отставание памяти (Latency) и рукопожатие (RF Handshake)

В реальном железе микросхемы памяти (ROM, DRAM) не отдают данные мгновенно — им требуется время доступа (Access Time / Wait States). В LIM2 это полностью симулируется!

### 6.1. Настройка задержки памяти
Задержка задается параметром `latency` (число тактов шины) и ножкой готовности `ready_pin` (по умолчанию `RF` — Ready Flag):

```python
# Память с задержкой в 2 такта шины:
ram = RAMDevice(start=0x0000, end=0x3FFF, latency=2, ready_pin="RF")
bus.attach(ram)

# Или через метод set_latency:
ram.set_latency(cycles=3, ready_pin="RF")
```

### 6.2. Временная диаграмма цикла шины (Bus Cycle Handshake)

```text
ТАКТ 1 (Start Read):    CPU: ADDR=0x1000, RD=1  -->  RAM: видит RD, сбрасывает RF=0 (BUSY)
ТАКТ 2 (Wait State T1): CPU: видит RF=0 (ждет)  -->  RAM: отсчитывает задержку (остался 1 такт)
ТАКТ 3 (Wait State T2): CPU: видит RF=0 (ждет)  -->  RAM: отсчитала задержку, ставит RF=1 (READY)
ТАКТ 4 (Data Capture):  CPU: видит RF=1, считывает данные DATA, сбрасывает RD=0
```

### 6.3. Как использовать в коде:

#### Вариант А: Автоматическое рукопожатие через `bus.read_handshake`
```python
# Процессор делает запрос, шина отрабатывает такты ожидания и возвращает данные:
data, wait_cycles = self.bus.read_handshake(0x1000)
print(f"Прочитан байт 0x{data:02X}, память задержала процессор на {wait_cycles} тактов.")
```

#### Вариант Б: Пошаговая симуляция ножек вручную
```python
# 1. Процессор выставляет сигнал чтения:
self.bus.pins.RD.set(1)
ram.start_read(offset=0x10)

# В этот момент ножка RF равна 0!
assert self.bus.pins.RF.get() == 0

# 2. Процессор крутится в цикле ожидания (Wait States):
waited_cycles = self.wait_for_pin("RF")

# 3. Ножка RF стала равной 1! Считываем данные и снимаем строб RD:
data = self.bus.read8(0x1010)
self.bus.pins.RD.set(0)
```

## 7. Разработка собственных внешних устройств (`devices.py`)

Для создания любого периферийного модуля унаследуйте класс `BaseDevice`:

```python
from devices import BaseDevice

class MyCustomDevice(BaseDevice):
    def __init__(self, start: int, size: int = 16, name: str = "MY_DEV"):
        # Задаем базовый адрес и размер области памяти
        super().__init__(start=start, size=size, name=name)
        self.state = 0

    def read(self, offset: int) -> int:
        """Чтение байта процессором (offset от 0 до size-1)."""
        if offset == 0:
            return self.state
        return self._raw[offset]

    def write(self, offset: int, value: int):
        """Запись байта процессором."""
        val8 = value & 0xFF
        if offset == 0:
            self.state = val8
            # Пример: генерация сигнала на ножке шины
            if self.bus is not None:
                self.bus.pins.IRQ.pulse()
        else:
            self._raw[offset] = val8

    def on_step(self):
        """Вызывается на каждом такте выполнения процессора."""
        pass

    def render_panel(self) -> str:
        """Опциональный графический ASCII-виджет прямо в дашборде."""
        return f"┌── [{self.name}] ──┐\n│ STATE: 0x{self.state:02X} │\n└───{'─'*len(self.name)}──┘"
```

## 8. Внешний графический пиксельный монитор ([`addons/pixel_monitor.py`](../addons/pixel_monitor.py))

Для демонстрации неограниченных возможностей расширения создан отдельный внешний модуль графического дисплея высокой четкости с настоящим окном ОС на базе Tkinter.

### Особенности `PixelMonitorDevice`:
- **Вынесен в отдельную папку `addons/`**: не навязывается ядру и не открывает лишних окон, пока он вам не нужен.
- **Окно ОС (Tkinter GUI):** работает в фоновом потоке, масштабирует пиксели (например `scale=6`), частота кадров до 60 FPS.
- **Цветовой режим RGB332:** 256 сочных цветов без палитры (3 бита R, 3 бита G, 2 бита B), 1 байт = 1 пиксель.
- **ANSI TrueColor превью:** в терминале отображает картинку через полублоки `▀`.

### Как подключить:
В файле `sim.py`:
```python
from addons.pixel_monitor import PixelMonitorDevice

def setup_platform(bus: MemoryBus):
    bus.attach(RAMDevice(0x0000, 0x3FFF, "RAM"))
    # Подключаем графический пиксельный дисплей 64x64:
    bus.attach(PixelMonitorDevice(
        start=0x4000,
        width=64,
        height=64,
        scale=6,
        mode="rgb332",
        show_gui=True
    ))
```

Чтобы нарисовать точку по координатам `(x=10, y=5)` красным цветом (`0xE0`):
$$\text{Адрес} = 0x4000 + (5 \times 64) + 10 = 0x414A$$
```python
self.bus.write8(0x414A, 0xE0)
```
Точка мгновенно отобразится в графическом окне!

## 9. Интерактивное меню отладчика (`-i`)

В интерактивном режиме отладчика доступно мощное меню управления:

| Команда | Описание |
|---|---|
| `<Enter>` / `s` / `step` | Выполнить ровно 1 такт/команду |
| `do <N>` | Выполнить `N` тактов (например: `do 20`) |
| `r` / `run` / `cont` | Непрерывный запуск (пауза по `Ctrl+C`) |
| `delay <ms>` | Задержка анимации в миллисекундах (например: `delay 50`) |
| `b <addr>` | Установить или снять точку останова (breakpoint) |
| `r0=0x42` / `r1=100` | Прямое изменение любого регистра |
| `set <addr> <b1> <b2>...` | Запись байтов в память (напр: `set 0x8000 0x48 0x69`) |
| `write <dev> <offset> <val>` | Запись в устройство (напр: `write MONITOR 0 "HELLO"`) |
| `save [file]` | Сохранить полный снимок машины (память, устройства, регистры, PC) в файл |
| `load [file]` | Загрузить полный снимок машины или бинарник прямо в работающий симулятор |
| `layout auto / 1col / 2col / 3col` | Переключение многоколоночного режима |
| `move / cols` | Показать распределение блоков по колонкам и их высоты |
| `move <блок> <1\|2\|3>` | Перенести блок в указанную колонку (напр: `move screen 2`) |
| `move <блок> next / prev` | Сдвинуть блок в следующую/предыдущую колонку (`+` / `-`) |
| `wrap on / off` | Включить/выключить автоперенос блоков при нехватке высоты |
| `height <N\|auto>` | Ограничить максимальную высоту колонки в строках |
| `view cpu / code / mem / screen / map` | Включение / выключение отдельных панелей |
| `reset` | Сбросить процессор в исходное состояние |
| `q` / `quit` / `exit` | Выход из симулятора (с автосохранением дампа, если включен `-L`) |

## 10. Долговременная работа (Long-Term Work, `-L`) и снимки памяти

### Зачем нужен режим `-L`:
При отладке больших программ, операционных систем или длительных вычислений часто необходимо прервать работу симулятора, выключить компьютер, а затем продолжить ровно с того же места, сохранив:
- Все значения регистров общего назначения (`R0`..`R7`, `ACCA`, `ACCB`, `SP` и др.)
- Регистр флагов `FREG`
- Текущий счетчик команд `PC`
- Количество выполненных тактов `step_count`
- Содержимое оперативной памяти (RAM)
- Внутреннее состояние памяти всех внешних устройств (буфер экрана, порты)

### Как использовать флаг `-L`:
```bash
# 1. Первый запуск с прошивкой и автосохранением в дефолтный lim2_state.dump:
python3 sim.py kernel.bin -i -L

# 2. Пошагово работаем, пишем в регистры, меняем экран...
# Выходим из симулятора (команда q или Ctrl+C):
# [LONG-TERM] Состояние симулятора успешно сохранено в 'lim2_state.dump'

# 3. Повторный запуск БЕЗ указания прошивки (симулятор продолжит работу с сохраненной точки!):
python3 sim.py -i -L
# [LONG-TERM] Восстановлено состояние из дампа 'lim2_state.dump' (PC: 0x0124, тактов: 1540)
```

### Именованные дампы:
Можно вести несколько независимых сессий:
```bash
python3 sim.py os.bin -i -L session_boot.dump
python3 sim.py app.bin -i -L session_calc.dump
```

## 11. Настройка колонок и автоперенос по высоте экрана

### 11.1. Доступные инфо-блоки:
Интерфейс симулятора состоит из 5 ключевых модулей:
- `cpu` (регистры процессора, микросхемы, АЛУ, флаги)
- `code` (дизассемблер потока инструкций с подсветкой текущего `PC`)
- `screen` (видеомониторы и текстовые экраны с рамками)
- `mem` (память устройств, шестнадцатеричные дампы с подсветкой изменений)
- `map` (графическая карта шины памяти в стиле *diskmgmt*)

### 11.2. Перемещение любого блока в интерактивном режиме:
Вы можете в любой момент на лету переместить любой блок в нужную колонку:
```text
(cpu) > move screen 2         # переносит видеомонитор во 2-ю колонку
(cpu) > move screen 3         # переносит видеомонитор в 3-ю колонку
(cpu) > move code 1           # переносит дизассемблер в 1-ю колонку
(cpu) > move cpu 2            # переносит регистры во 2-ю колонку
(cpu) > move mem 1            # переносит память в 1-ю колонку
```

Циклический сдвиг:
```text
(cpu) > move screen next      # сдвигает монитор в следующую колонку (1 -> 2 -> 3 -> 1)
(cpu) > move screen prev      # сдвигает монитор в предыдущую колонку (3 -> 2 -> 1 -> 3)
```

Просмотр текущего распределения:
```text
(cpu) > move                  # или команда: cols
```

### 11.3. Автоматический перенос при превышении высоты экрана (Height Auto-Wrap):
Если окно вашего терминала невысокое (например, 24 или 30 строк), вертикальное размещение нескольких блоков (например, микросхемы процессора + видеомонитор) может привести к тому, что экран не поместится и потребуется вертикальная прокрутка.

Симулятор **автоматически отслеживает высоту окна терминала**:
- Если суммарная высота блоков в колонке превышает доступную высоту экрана, лишние блоки **автоматически "перетекают" в соседнюю свободную колонку**!
- Управление автопереносом:
  - `wrap on` — включить умный перенос по высоте (включен по умолчанию).
  - `wrap off` — выключить перенос (блоки жестко фиксируются в заданных колонках).
  - `height <число>` — явно задать ограничение высоты в строках (например `height 20`).
  - `height auto` — вернуть автоматическое определение по размеру терминала.

### 11.4. Настройка колонок и переноса в коде Python (`sim.py`):
```python
from ui import UIConfig
from runner import SimulationRunner

# Задаем желаемое распределение блоков и автоперенос:
cfg = UIConfig(
    layout_mode="auto",
    block_columns={
        "cpu": 1,
        "screen": 2,   # Монитор сразу во 2-й колонке!
        "code": 1,     # Дизассемблер в 1-й колонке
        "mem": 3,
        "map": 3,
    },
    auto_height_wrap=True,  # Включен перенос по высоте
    max_col_height=None     # Адаптивно по высоте окна терминала
)

runner = SimulationRunner(cpu, ui_config=cfg)
runner.run_interactive()
```

### 11.5. Настройка через флаги командной строки:
```bash
# Разместить экран в колонке 2, а дизассемблер в колонке 1:
python3 sim.py demo.bin -i --col-screen 2 --col-code 1

# Отключить автоперенос по высоте:
python3 sim.py demo.bin -i --no-wrap
```
